- 사다리(낮은 단부터): 일변수 미분·테일러 전개(알고 있음) → 편미분과 gradient(애매함) → 벡터값 함수의 Jacobian과 shape 규칙(아예 모름) → 행렬에 대한 gradient·연쇄 법칙(아예 모름) → 역전파와 자동미분, Hessian·다변수 테일러(아예 모름).
- 학습 수준: 사다리에서 "아예 모름"인 첫 단부터 끝 단까지. "애매함"인 단은 수업에 일부 넣는다.
- 오개념: "gradient는 항상 입력과 같은 모양의 열벡터다"라고 답했다.

## cpu-cache

### 상황
- 작업: 게임의 파티클 시스템 업데이트 루프(매 프레임 위치에 속도를 더한다, 파티클 10만 개)를 짠다. 파티클 데이터를 AoS(`struct Particle` 배열)로 둘지 SoA(필드별 배열)로 둘지 정해야 하는데, CPU 캐시가 성능을 어떻게 좌우하는지 판단 근거를 모른다. 학습 자료를 만들어 달라.
- 배경: C++로 게임 로직을 짜 본 주니어 클라이언트 개발자. 포인터·배열·구조체는 안다. 성능 프로파일링 경험은 거의 없다.

### 진단 결과(고정)
- 사다리(낮은 단부터): 메모리 계층과 지연 차이(애매함) → 캐시 라인 단위로 가져오기(아예 모름) → 공간 지역성과 접근 패턴(아예 모름) → 하드웨어 프리페치(아예 모름) → AoS/SoA와 루프가 쓰는 필드 비율(이름만 앎, 애매함).
- 학습 수준: 캐시 라인. 메모리 계층은 애매함이라 수업에 일부 넣는다.
- 오개념: "구조체를 쓰면 데이터가 모여 있으니 항상 캐시에 유리하다"고 답했다.
