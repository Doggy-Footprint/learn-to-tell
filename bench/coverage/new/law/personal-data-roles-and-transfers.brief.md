# 법 · 개인정보 처리의 주체 관계: 수집·이용, 처리위탁, 제3자 제공
## 상황
- 작업: 고객사 데이터를 외부 클라우드·이메일 발송·분석 서비스에 넘기는 아키텍처를 승인하기 전에, 각 데이터 흐름이 처리위탁인지 제3자 제공인지와 필요한 절차를 판단한다. 학습 자료를 만들어 달라.
- 배경: B2B SaaS의 개발 리드. 데이터 파이프라인과 외부 API 연동을 설계하지만 법학 교육은 받은 적 없다. 한국 개인정보 보호법 기준. 해외 이전 세부 요건과 가명정보 특례는 다루지 않는다.
## 진단 결과(고정)
- 사다리(낮은 단부터): 개인정보는 정보주체를 알아볼 수 있는 정보다(알고 있음) → 처리자는 법적 근거(동의, 계약 이행 등)가 있어야 수집·이용할 수 있다(애매함) → 데이터를 넘기는 것은 누구의 이익을 위한 것인가에 따라 처리위탁과 제3자 제공으로 나뉜다(아예 모름) → 각 관계마다 책임 주체와 필요한 절차(공개·계약, 별도 동의 등)가 다르다(아예 모름)
- 학습 수준: 처리 근거, 위탁과 제3자 제공의 구별 기준, 관계별 책임과 절차
- 오개념: "외부 서버로 데이터를 보내기만 하면 전부 '제3자 제공'이라 사용자 동의를 다시 받아야 하고, 반대로 계약서만 쓰면 무엇이든 위탁이다"라고 답했다.
## 장면 목록
1. 우리 파이프라인의 화살표는 모두 같은 화살표인가 / hook
2. 처리자, 정보주체, 그리고 근거 / define
3. 이메일 발송 대행사에 주소를 넘기면? / predict
4. 위탁과 제3자 제공을 가르는 질문 / explain
5. 같은 데이터 이동, 다른 목적 / compare
6. 우리 아키텍처의 흐름 분류하기 / explore
7. 사고가 나면 책임은 누구에게 / quiz
8. 정리: 흐름별 절차 지도 / final summary
## 그림
### F1 데이터 흐름 아키텍처 위의 법적 관계층
- 보여 주는 것: 실제 SaaS 아키텍처 다이어그램(이용자 브라우저 → 자사 API → 클라우드 DB, 이메일 발송 서비스, 분석 서비스, 제휴 광고사). 처음에는 모든 화살표가 같은 회색. 레이어 토글을 켜면 화살표가 법적 관계(수집, 위탁, 제3자 제공)에 따라 색과 선 모양이 바뀐다.
- 속성:
  - P1 [I] "기술 관점 / 법적 관점" 레이어 토글 — 필수, 같은 화살표가 법적으로는 다르다는 hook의 반전
  - P2 [E] 토글 후 제3자 제공 화살표(제휴 광고사)가 가장 먼저 눈에 띄는 색 — 필수, 위험도가 가장 큰 흐름
  - P3 [G] 노드 배치는 기술 레이어와 법적 레이어에서 동일, 바뀌는 것은 화살표 표기만 — 필수, 물리적 흐름은 같고 평가만 다름
  - P4 [X] "예시 아키텍처, 실제 분류는 계약과 실제 운영에 따라 달라짐" 표시 — 필수, 단정 방지
### F2 처리의 세 주체 관계도
- 보여 주는 것: 정보주체(이용자), 개인정보처리자(자사), 그리고 처리자 밖의 두 위치(수탁자, 제3자)를 배치한 관계도. 정보주체→처리자 화살표에 처리 근거 라벨(동의, 계약 이행에 필요, 법령상 의무 등; 개인정보 보호법 제15조 제1항 각 호)을 붙인다. B2B라서 고객사가 처리자이고 자사가 수탁자인 경우를 별도 탭으로 보여 준다.
- 속성:
  - P1 [G] 수탁자는 처리자 경계선 안쪽 점선 영역, 제3자는 경계선 바깥 — 필수, "처리자의 손발"인지 "독립된 처리자"인지의 공간적 대응
  - P2 [X] 처리 근거 목록 중 동의는 여러 근거 중 하나라는 표시 — 필수, "언제나 동의"라는 오해 방지
  - P3 [I] 탭 전환: B2C(자사가 처리자) / B2B(고객사가 처리자, 자사가 수탁자) — 필수, 학습자 회사가 어느 위치인지 자체가 바뀜
  - P4 [X] "공동 처리 등 다른 관계는 생략" 표시 — 필수, 단순화 명시
### F3 이메일 발송 대행 예측
- 보여 주는 것: 자사가 이용자 이메일 주소를 발송 대행사에 넘겨 자사 공지 메일을 보내는 흐름. 학습자가 "위탁 / 제3자 제공 / 어느 쪽도 아님"을 고르면, F2 관계도에서 대행사 노드가 처리자 경계 안쪽(수탁자)으로 들어가며 공개된다.
- 속성:
  - P1 [I] 선택 확정 후 공개 — 필수, predict 장면
  - P2 [G] 공개 시 노드가 F2의 수탁자 영역으로 이동 — 필수, 앞 그림의 공간 규칙으로 결론을 읽게
  - P3 [X] 판단 근거 한 줄: 대행사는 자사 업무를 대신 처리하고 자기 목적으로 쓰지 않음 — 필수
  - P4 [X] "대행사가 그 주소로 자기 광고를 보내면 결론이 바뀜" 주석 — 필수, 다음 장면의 연결고리이자 조건부 결론의 사실 표시
### F4 구별 판단 흐름도
- 보여 주는 것: 데이터를 받는 쪽을 놓고 묻는 질문 사슬. Q1 누구의 업무·이익을 위해 처리하는가(넘기는 쪽 vs 받는 쪽) → Q2 받는 쪽이 자기 목적으로 이용할 수 있는가 → Q3 넘기는 쪽의 지휘·감독을 받는가. 끝단에 "처리위탁(제26조)" 또는 "제3자 제공(제17조)" 결론과 각 절차(위탁: 문서 계약·위탁 사실 공개·수탁자 감독 / 제3자 제공: 원칙적으로 정보주체 동의 또는 법정 사유, 동의 시 고지 사항).
- 속성:
  - P1 [G] 분기 구조, 핵심 분기(Q1)를 맨 위·가장 큰 노드로 — 필수, 판례·실무의 주된 구별 기준이 "누구의 이익"임
  - P2 [X] 결론 노드에 조문 번호와 필요 절차 요약 — 필수
  - P3 [X] "계약서 명칭이 아니라 실질로 판단" 표시 — 필수, 오개념 후반부("계약서만 쓰면 위탁") 직접 겨냥
  - P4 [T] 단계별로 질문이 하나씩 열림 — 선택, explain 장면의 읽기 순서 통제
  - P5 [E] 경계 사례(예: 분석 서비스가 데이터로 자기 모델을 개선)는 흐름도 옆 "판단 어려움" 주석 영역 — 선택, 불확정 영역을 사실대로
### F5 같은 이동, 다른 목적 비교
- 보여 주는 것: 동일한 데이터 묶음(이름·이메일·구매 이력)이 동일한 분석 회사로 가는 흐름을 두 패널로. 패널 A: 자사 대시보드를 만들어 주는 용도로만 처리, 결과는 자사에만 반환. 패널 B: 분석 회사가 자기 광고 상품 개발에도 이용. A는 처리자 경계 안(위탁), B는 경계 밖(제3자 제공).
- 속성:
  - P1 [S] 두 패널의 노드·데이터·화살표 배치가 동일, 달라지는 것은 "이용 목적" 라벨과 되돌아오는 화살표 유무 — 필수, 변수 하나만 바꿈
  - P2 [E] 목적 라벨을 강조색으로 — 필수, 결론을 바꾼 요소가 먼저 보이게
  - P3 [G] B에서 분석 회사 안에 데이터가 머무르는 자체 저장소 아이콘 추가 — 필수, 받는 쪽의 독자적 이용을 시각화
  - P4 [X] 각 패널 아래 필요 절차 비교 한 줄 — 필수
### F6 아키텍처 흐름 분류 탐색판
- 보여 주는 것: F1의 아키텍처에서 각 화살표를 클릭해 분류(수집·이용 / 위탁 / 제3자 제공)와 필요 절차를 지정한다. 각 화살표에 받는 쪽의 이용 목적 카드가 붙어 있다. 목표: 모든 흐름을 올바르게 분류하고 빠진 절차가 없는 상태 만들기.
- 속성:
  - P1 [I] 화살표 선택 → 분류 지정 → 절차 체크, 전부 맞으면 목표 달성 — 필수, explore 장면
  - P2 [X] 오답 시 F4 흐름도의 어느 질문에서 갈렸는지 표시 — 필수, 판단 근거로 되돌아가게
  - P3 [E] 미분류 화살표는 점선으로 남아 진행 상황이 보임 — 선택
  - P4 [X] 클라우드 인프라(IaaS) 흐름에 "단순 보관 인프라의 위탁 해당 여부는 견해가 갈릴 수 있음" 주석 — 필수, 불확정 영역 표시
### F7 사고 시 책임 경로도
- 보여 주는 것: 수탁자 쪽에서 유출 사고가 난 경우와 제3자 쪽에서 사고가 난 경우를 나란히. 위탁에서는 수탁자의 위반으로 생긴 손해에 대해 수탁자를 처리자의 소속 직원으로 보는 배상책임 규정(제26조)에 따라 책임 화살표가 위탁자(자사)까지 거슬러 올라오고, 제3자 제공에서는 받은 쪽이 독립 처리자로서 자기 책임을 진다(다만 자사의 제공 자체가 적법했는지는 별도).
- 속성:
  - P1 [G] 책임 화살표의 방향과 도달 범위 — 필수, 관계 구별이 실무상 왜 중요한지의 결론
  - P2 [X] "형사·행정 책임의 세부는 생략, 민사 배상 관계 중심" 표시 — 필수, 단순화 명시
  - P3 [I] 퀴즈 응답 후에만 책임 화살표 공개 — 필수, quiz 장면
  - P4 [E] 위탁자로 거슬러 오는 화살표를 가장 굵게 — 필수, 오개념("넘기면 끝")과 반대되는 사실
### F8 흐름별 절차 지도
- 보여 주는 것: F1 아키텍처를 법적 레이어 상태로 축소해 두고 각 화살표 옆에 필요한 절차 태그(처리방침에 위탁 사실 공개, 위탁 계약 문서, 제3자 제공 별도 동의와 고지 항목, 처리 근거 기록)를 고정.
- 속성:
  - P1 [S] 절차 태그가 해당 흐름 화살표에 붙음 — 필수, 조치와 흐름의 대응
  - P2 [X] "법률 자문을 대신하지 않음, 해외 이전·가명정보 요건 별도" 표시 — 필수, 다루지 않은 범위의 사실 표시
  - P3 [E] 오개념 두 부분(모든 전송=제3자 제공, 계약서=위탁)을 반박하는 두 흐름을 강조 — 필수, 학습 목표 재확인
