# 법 · 계약의 성립과 약관의 효력
## 상황
- 작업: 자사 SaaS 이용약관 개정안(가입 화면 동의 방식, 면책 조항, 일방 변경 조항)을 승인할지 결정한다. 학습 자료를 만들어 달라.
- 배경: 개발 리드로서 가입 플로우와 약관 동의 UI를 설계한다. 법학 교육은 받은 적 없고, 약관은 "체크박스에 동의하면 전부 유효"라고 생각해 왔다. 한국법(민법, 약관의 규제에 관한 법률) 기준.
## 진단 결과(고정)
- 사다리(낮은 단부터): 계약은 청약과 승낙의 합치로 성립한다(알고 있음) → 의사표시는 상대방에게 도달해야 효력이 생긴다(애매함) → 약관은 명시·설명되어야 계약 내용으로 편입된다(애매함) → 편입된 조항도 불공정하면 무효가 되고, 뜻이 애매하면 작성자에게 불리하게 해석된다(아예 모름)
- 학습 수준: 도달주의, 약관의 편입 통제, 내용 통제와 해석 원칙
- 오개념: "사용자가 '전체 동의'에 체크했으니 약관의 모든 조항이 그대로 효력이 있다"라고 답했다.
## 장면 목록
1. 체크박스 하나로 무엇이 묶이는가 / hook
2. 청약·승낙과 도달 / explain
3. 이 면책 조항은 효력이 있을까 / predict
4. 약관이 계약이 되기까지의 세 관문 / steps
5. 중요 조항의 설명 여부를 바꿔 보기 / compare
6. 조항을 관문에 통과시켜 보기 / explore
7. 애매한 조항은 누구에게 유리한가 / quiz
8. 정리: 동의 UI와 조항 설계 체크리스트 / final summary
## 그림
### F1 가입 화면과 계약의 대응도
- 보여 주는 것: 왼쪽에 SaaS 가입 화면 와이어프레임(약관 링크, "전체 동의" 체크박스, 가입 버튼), 오른쪽에 법적 요소(청약, 승낙, 약관 조항 목록). 화면 요소마다 대응하는 법적 요소로 선이 이어진다. "전체 동의" 체크는 약관 전체와 이어지지만 일부 조항으로 가는 선은 점선(편입·효력 미확정)으로 그린다.
- 속성:
  - P1 [G] 화면 요소와 법적 요소의 1:1 또는 1:다 연결선 — 필수, 학습자가 익숙한 UI를 법적 개념에 고정하는 다리 역할
  - P2 [E] 점선으로 표시된 "체크했지만 효력이 확정되지 않은" 연결이 가장 먼저 눈에 띄어야 함 — 필수, 오개념을 직접 겨냥
  - P3 [X] 와이어프레임 위 "예시 화면, 실제 서비스 아님" 표시 — 필수, 그림이 특정 회사 화면으로 읽히지 않게
  - P4 [I] 화면 요소에 마우스를 올리면 대응 법적 요소가 강조됨 — 선택, 대응 탐색 보조
  - P5 [S] 좌(사실 세계) / 우(법률 관계) 2단 구성 — 필수, 사실과 법적 평가의 층위 구분
### F2 청약과 승낙의 시간선(도달주의)
- 보여 주는 것: 회사와 이용자 두 수평 레인, 그 사이를 오가는 의사표시 화살표. 각 화살표는 "발신" 점과 "도달" 점을 갖고, 효력 발생 표시는 도달 점에 붙는다. 회사의 "청약의 유인"(가입 페이지 게시) → 이용자의 청약(가입 신청) → 회사의 승낙(가입 완료 처리/메일)으로 단계가 진행된다.
- 속성:
  - P1 [T] 단계 버튼으로 화살표가 하나씩 진행되며, 도달 순간에만 효력 마크가 켜짐 — 필수, 발신과 도달의 시점 차이가 핵심
  - P2 [G] 화살표 시작점(발신)과 끝점(도달)이 시간축에서 떨어져 있음 — 필수, 도달주의(민법 제111조 제1항)의 시각화
  - P3 [X] 시간축에 "축척 없음, 순서만 의미" 표시 — 필수, 간격이 실제 시간 길이로 읽히지 않게
  - P4 [X] 게시 페이지가 청약이 아니라 청약의 유인일 수 있다는 주석 — 선택, 서비스 구조에 따라 달라지는 판단임을 표시
  - P5 [E] 계약 성립 순간(승낙 도달)을 굵은 세로선으로 강조 — 필수, "언제 묶이는가"가 이 그림의 결론
### F3 약관 통제의 세 관문
- 보여 주는 것: 조항 카드들이 왼쪽에서 들어와 세 개의 관문을 차례로 통과하는 파이프라인. 관문 1 편입 통제(명시·설명의무, 약관규제법 제3조), 관문 2 해석(객관적·통일적 해석, 작성자 불리 원칙, 같은 법 제5조), 관문 3 내용 통제(신의성실 위반 불공정 조항 무효, 같은 법 제6조 및 개별 금지조항 제7조 이하). 관문을 통과하지 못한 카드는 아래로 떨어져 "계약 내용 아님" 또는 "무효" 통에 들어간다.
- 속성:
  - P1 [G] 관문의 순서가 왼쪽→오른쪽으로 고정 — 필수, 편입되지 않은 조항은 해석·내용 통제 대상이 되지도 않는다는 논리적 선후
  - P2 [S] 두 탈락 통을 구분("편입 안 됨" vs "편입됐으나 무효") — 필수, 결과는 비슷해도 근거가 다름
  - P3 [T] 단계별로 카드가 이동하는 애니메이션 — 필수, steps 장면의 진행 단위
  - P4 [X] 각 관문 아래 근거 조문 표기 — 필수, 학습자가 이후 원문을 찾아볼 수 있게
  - P5 [X] "개별 협상한 조항은 약관이 아님, 그림에서 생략" 표시 — 선택, 단순화 명시
  - P6 [E] 체크박스 아이콘이 첫 관문 앞에만 있음 — 필수, 동의가 관문 1의 일부일 뿐임을 보여 줌
### F4 면책 조항 예측 카드
- 보여 주는 것: 예시 조항 "회사는 서비스 장애로 인한 어떠한 손해에 대해서도 책임지지 않는다"를 카드로 보여 주고, 학습자가 "유효/무효/일부만 무효" 중 하나를 고른 뒤 공개 시 카드가 F3 관문 3에서 걸리는 위치(고의·중과실 책임 배제 금지, 약관규제법 제7조)를 표시한다.
- 속성:
  - P1 [I] 세 선택지 중 하나를 확정해야 공개 버튼이 활성화 — 필수, predict 장면의 약속
  - P2 [G] 공개 후 카드가 F3의 관문 3 위치로 이동 — 필수, 앞 그림과 같은 공간 안에서 결론을 읽게
  - P3 [X] 조항 문구 중 "어떠한 손해"에 밑줄과 주석 — 필수, 무효 판단의 핵심 단어
  - P4 [X] "구체적 효력은 사안별 판단, 예시 결론" 표시 — 필수, 그림이 단정적 법률 의견으로 읽히지 않게
### F5 설명의무 이행 여부 비교
- 보여 주는 것: 같은 중요 조항(예: 자동 갱신과 요금 인상)을 두 조건에서 나란히 그린다. 조건 A: 약관 전문 링크만 있고 체크박스 하나. 조건 B: 해당 조항을 가입 화면에 별도로 요약 표시하고 개별 확인. A에서는 카드가 관문 1에서 떨어지고, B에서는 통과한다.
- 속성:
  - P1 [S] 두 패널이 같은 레이아웃·같은 조항, 차이는 화면 표시 방식 하나 — 필수, compare 장면은 변수 하나만 바꿔야 결론이 성립
  - P2 [E] 차이 나는 화면 요소(요약 박스)를 강조색으로 표시 — 필수, 무엇이 결과를 바꿨는지 먼저 보이게
  - P3 [X] "설명의무가 면제되는 경우(거래상 일반적이고 공통된 내용 등)는 생략" 표시 — 필수, 단순화 명시
  - P4 [X] "B가 항상 충분하다는 보장은 아님" 주석 — 필수, 그림이 안전한 UI 처방으로 과대해석되지 않게
### F6 조항 분류 탐색판
- 보여 주는 것: 여러 조항 카드(일방적 서비스 변경, 고의·중과실 면책, 데이터 이전 거부, 관할 법원 지정, 환불 불가)를 학습자가 끌어 F3 관문의 탈락 통 또는 통과 영역에 놓는다. 목표: 모든 카드를 옳은 위치에 놓기. 놓을 때마다 근거 한 줄이 뜬다.
- 속성:
  - P1 [I] 카드 드래그 앤 드롭, 목표 달성 시 완료 표시 — 필수, explore 장면의 목표
  - P2 [X] 판정 근거를 조문 단위로 짧게 표시 — 필수, 정답만이 아니라 이유를 익히게
  - P3 [E] 정답이 "사안에 따라 다름"인 카드는 회색 영역에 놓게 하고 별도 표시 — 필수, 법적 판단의 불확정성을 사실대로 표현
  - P4 [S] F3과 같은 관문 배치 재사용 — 선택, 학습 부하 감소
### F7 작성자 불리 해석의 저울
- 보여 주는 것: 애매한 조항 "회사는 필요한 경우 서비스를 변경할 수 있다"에 대해 두 해석(회사에 유리: 어떤 변경이든 가능 / 이용자에 유리: 중요하지 않은 변경만 가능)을 저울 양쪽에 놓고, 해석 원칙을 적용하면 이용자 쪽으로 기우는 모습.
- 속성:
  - P1 [G] 저울의 기울기 방향 — 필수, 결론(고객에게 유리하게, 약관규제법 제5조 제2항)
  - P2 [X] "저울의 기울기 정도는 의미 없음, 방향만 의미" 표시 — 필수, 정도가 정량으로 읽히지 않게
  - P3 [T] 원칙 적용 버튼을 누를 때 저울이 기우는 짧은 전환 — 선택, 원칙이 결과를 만든다는 인과 강조
  - P4 [X] "먼저 객관적 해석을 시도하고, 그래도 애매할 때 적용" 주석 — 필수, 적용 순서를 사실대로
### F8 정리 체크리스트 지도
- 보여 주는 것: F3 파이프라인을 축소해 배경에 두고 각 관문 위에 개발 리드가 확인할 항목(중요 조항 별도 표시·확인 로그 보존 / 모호한 문구 제거 / 고의·중과실 면책·일방 변경 조항 검토)을 고정 핀으로 단다.
- 속성:
  - P1 [S] 체크 항목이 해당 관문 위치에 핀으로 고정 — 필수, 조치와 법적 근거의 대응
  - P2 [X] "법률 자문을 대신하지 않음" 표시 — 필수, 책임 범위의 사실 표시
  - P3 [E] 오개념을 깨는 항목(체크박스는 관문 1의 일부일 뿐)을 맨 앞에 강조 — 필수, 학습 목표 재확인
