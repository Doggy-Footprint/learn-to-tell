"투박하다"를 분해하기

세련됨은 감각이 아니라 여러 개의 작은 결정이 일관되게 쌓인 결과다. 이 문서는 관리자 화면을 "투박하게" 만드는 요소를 6가지로 쪼개고, 각각을 직접 켜고 끄며 차이를 체감한 뒤, 우리 화면에서 어디부터 고칠지 판단하는 체크리스트로 마무리한다.

0실험실: 하나씩 켜 보기

아래는 흔한 "투박한" 회원 관리 화면이다. 데이터·기능·마크업은 그대로 두고 CSS만 원리별로 덧입힌다. 하나씩 켜면서 어느 것이 가장 큰 차이를 내는지 느껴 보자.

관찰 포인트. 대부분의 사람은 "간격"과 "색"을 켰을 때 가장 큰 변화를 느낀다. 투박함의 70%는 숨 쉴 공간이 없고, 모든 것이 같은 세기로 소리친다는 데서 온다. 새로운 장식을 더하는 게 아니라 덜어내고 위계를 만드는 것이 핵심이다.

1간격 (Spacing)

가장 효과가 크고, 가장 쉽게 고칠 수 있다.

원리 ① 스케일을 정하고 그 값만 쓴다

4px 배수(4·8·12·16·24·32·48·64)만 허용하면, 개별 결정이 사라지고 화면 전체에 리듬이 생긴다. margin: 13px, padding: 7px 9px 같은 값이 코드에 흩어져 있다면 그 자체가 투박함의 신호다.

원리 ② 근접성: 관련된 것은 가깝게, 다른 그룹은 멀게

간격 자체보다 간격의 차이가 정보를 전달한다. 라벨과 입력창 사이(4–8px)는 필드와 필드 사이(16–24px)보다 확실히 좁아야 그룹이 읽힌다.

원리 ③ 생각보다 넉넉하게

개발자가 "적당하다"고 느끼는 패딩은 대개 디자이너 기준의 절반이다. 의심되면 두 배로 늘려본 뒤 줄여 나가라. 관리자 화면은 밀도가 중요하지만, 밀도는 행 높이(테이블 셀 패딩)로 조절하고 컨테이너 바깥 여백은 아끼지 않는다.

2타이포그래피

크기 하나로 위계를 만들려 하면 투박해진다. 크기·굵기·색 세 축을 같이 쓴다.

세련된 쪽은 오히려 라벨을 작고 흐리게 했다. 중요한 것을 키우는 것만큼 덜 중요한 것을 낮추는 게 효과적이다.

3색

투박한 화면은 색이 "많아서"가 아니라 "세서" 투박하다.

원리 ① 화면의 90%는 무채색이다

배경·텍스트·테두리는 회색 계열 한 팔레트(예: zinc, slate)에서 고른다. 순수 #000 텍스트 대신 #18181b 같은 아주 짙은 회색을 쓰면 대비는 유지하면서 날카로움이 빠진다.

50100200300 400500700900 accent

텍스트 3단계: 900(본문) · 500(보조) · 400(비활성/플레이스홀더). 테두리: 200. 배경 구분: 50.

원리 ② 강조색은 하나, 그리고 아껴 쓴다

화면에서 강조색(primary)이 칠해진 버튼은 보통 하나다. "회원 추가"와 "저장"이 둘 다 파란색이면 어느 것도 강조되지 않는다.

원리 ③ 상태색은 "연한 배경 + 진한 글자"

4경계와 깊이

선을 그어 나누는 대신, 공간과 배경으로 나눈다.

  • 테두리를 줄여라. 테이블의 모든 칸에 세로선까지 긋는 "엑셀 격자"는 투박함의 대표 원인. 가로 구분선 하나(또는 줄무늬 없이 여백만)로 충분하다.
  • 테두리는 연하게. #999가 아니라 #e4e4e7. 선은 보일 듯 말 듯해야 구조만 남고 소음은 사라진다.
  • 그림자는 아주 약하게. 0 1px 2px rgba(0,0,0,.05) 수준. 진하고 퍼진 그림자는 2010년대 느낌을 준다. 떠 있는 요소(드롭다운, 모달)만 조금 더 진하게.
  • 둥근 모서리를 통일. 버튼·입력 6–8px, 카드 10–12px, 배지는 완전 원형(999px). 0px과 4px과 12px이 섞이면 어색하다.
  • 중첩 반경 규칙. 안쪽 반경 = 바깥 반경 − 패딩. 카드(12px) 안에 패딩 4px로 버튼이 꽉 차면 버튼 반경은 8px.

5정렬

보이지 않는 선이 많을수록 정돈돼 보인다.

  • 텍스트는 왼쪽, 숫자는 오른쪽. 테이블의 가운데 정렬은 거의 항상 틀렸다. 금액·수량은 오른쪽 정렬 + tabular-nums 로 자릿수가 맞아야 비교가 된다.
  • 헤더도 데이터와 같은 방향으로. 숫자 열 헤더가 왼쪽이면 열이 "어긋나" 보인다.
  • 정렬 축을 줄인다. 페이지 제목, 필터, 테이블 첫 열의 왼쪽 끝이 한 선에 있는지 확인. 각자 다른 들여쓰기는 산만함의 원인.
  • 세로 중앙 정렬. 아이콘+텍스트, 제목+버튼 묶음은 align-items: center. 아이콘이 1–2px 내려가 있는 것만으로 "뭔가 이상하다"가 된다.

7모든 것을 묶는 것: 일관성

위 1–6은 "규칙"이고, 세련됨은 그 규칙이 예외 없이 지켜질 때 나온다.

한 화면만 예쁘게 고치는 것은 의미가 적다. 사용자가 투박하다고 느끼는 지점은 종종 페이지마다 버튼 높이가 다르고, 어떤 모달은 둥글고 어떤 모달은 각진 불일치다. 그래서 고치는 순서는 "화면"이 아니라 "토큰"이어야 한다.

:root { /* 간격 */ --space-1: 4px; --space-2: 8px; --space-3: 12px; --space-4: 16px; --space-6: 24px; --space-8: 32px; /* 글자 */ --text-xs: 12px; --text-sm: 14px; --text-base: 16px; --text-lg: 20px; --text-xl: 24px; /* 색 */ --gray-50: #fafafa; --gray-200: #e4e4e7; --gray-500: #71717a; --gray-900: #18181b; --accent: #4f46e5; /* 형태 */ --radius-sm: 6px; --radius-md: 8px; --radius-lg: 12px; /* 깊이 */ --shadow-sm: 0 1px 2px rgb(0 0 0 / .05); --shadow-md: 0 4px 12px rgb(0 0 0 / .08); }
컴포넌트 라이브러리를 쓰는데도 투박하다면? 대부분 원인은 라이브러리 바깥에 있다. ① 라이브러리 컴포넌트 사이의 레이아웃 여백을 직접 쓴 값으로 채움 ② 테마 토큰을 커스터마이즈하지 않고 기본 원색(primary blue 등)을 그대로 씀 ③ style={{ … }} 인라인으로 개별 화면에서 덮어씀. 라이브러리의 theme 설정 파일과, 페이지 레이아웃 컴포넌트를 먼저 보자.

✓우리 화면 진단 체크리스트

실제 관리자 페이지 하나를 열어 놓고 체크해 보자. 체크되지 않은 항목이 고칠 곳이다. 위에서부터 영향이 큰 순서다.

점수: 0 / 13

고치는 순서 제안

  1. 토큰부터 — 위 CSS 변수(또는 라이브러리 theme)를 먼저 정한다. 하루짜리 작업이고 이후 모든 수정의 기준이 된다.
  2. 레이아웃 셸 — 페이지 공통 컨테이너의 여백, 페이지 헤더(제목+액션) 컴포넌트를 하나로 만든다. 모든 화면에 즉시 퍼진다.
  3. 테이블 — 관리자 화면 면적의 대부분. 구분선·정렬·셀 패딩·배지만 고쳐도 체감이 크다.
  4. 버튼 위계 — primary / secondary / ghost / danger 4종으로 정리하고 화면별로 primary가 하나인지 검토.
  5. 상태 — focus, 로딩, 빈 상태. 눈에 덜 띄지만 "완성도"의 마지막 20%.

감을 키우는 연습법

  • 잘 만든 관리자 화면(Linear, Vercel, Stripe 대시보드 등)을 스크린샷 찍고, 개발자 도구로 padding·font-size·color 값을 직접 재 본다. 생각보다 여백은 크고 색은 흐리다.
  • 내 화면과 레퍼런스를 나란히 놓고, 위 6개 축 중 어느 것이 가장 다른지 한 단어로 말해 본다. "투박하다"를 "간격이 좁다"로 바꿔 말할 수 있으면 고칠 수 있다.
  • 화면을 흐리게(filter: blur(3px)) 보거나 눈을 가늘게 떠 본다. 그래도 위계가 보이면 잘 된 것이고, 회색 덩어리라면 대비·간격이 부족한 것이다.
이 문서의 모든 예시는 외부 의존성 없이 HTML/CSS로 작성되었다. 개발자 도구로 값을 직접 열어 보며 학습하자.
