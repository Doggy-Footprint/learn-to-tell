- 주요 주장 중 아래는 main이 코드와 파일을 직접 열어 확인했다.

  - 기준선 스크립트 수: 0, 0, 1.
  - `plan.md`의 사용자 의도 원문.
- 나머지는 검수자의 주장으로 남긴다.

## 실험의 정확성

1. **핵심 질문을 재지 않았다.**
   - `plan.md`의 의도 1번은 "일반적인 요청보다 양질"이다. 그런데 M1 끝 조건은 비용과 반복 횟수뿐이다.
   - 검수자는 기준선이 사용자의 실제 결정에 더 쓸모 있다고 본다. 3주제 중 2개(attacker, polished)다.
   - supply는 그림과 수치 모델은 skill이 낫고, 실무 내용은 기준선이 낫다고 본다.
2. **기준선은 같은 정보를 받지 않았다.**
   - skill 지시문은 진단 결과, 오개념, 수업 구조를 담았다. 기준선 지시문은 작업 문장과 배경뿐이다.
   - 그래서 "runtime이 상호작용을 보장한다"와 "지시가 상호작용을 요구한다"를 이 실험으로는 구분할 수 없다.
3. **"비용 목표 충족"은 v1과 비교할 때만 맞다.** 기준선과 비교하면 skill은 비용이 2–3배, 시간이 1.2–2.3배, 누적 처리량이 6–10배다.
4. **반복 횟수 목표는 지시로 강제한 값이다.** supply는 마지막 check가 실패한 상태로 제출됐고, 정답 검산이 찾은 오류도 고치지 않았다. 그런데도 "충족"으로 셌다.
5. **v1 대비 개선의 원인을 분리하지 않았다.**
   - M1은 여러 조건을 한꺼번에 바꿨다: runtime 도입, effort low, 검증 반복 제거, 예산 상한.
   - 같은 정책을 HTML 경로에 준 대조군이 없다.
   - 그래서 `plan.md`의 기각 사유 "agent가 페이지를 쓰는 구조는 v1처럼 실패한다"는 검증되지 않았다.
6. **param 이름 충돌을 잘못 분류했다.**
   - check는 model마다 자기 기본값으로 계산한다. 화면은 모든 model의 기본값을 한 표로 합치고, 뒤 model이 앞 model을 덮는다.
   - 따라서 수업 결함이 아니라 runtime의 의미 불일치다. check를 통과해도 화면 수치가 맞는다는 보장이 없다.
7. **계약이 만든 결함을 수업 결함으로 셌다.**
   - 그림 필수 규칙이 무관한 그림을 붙이게 했다.
   - drag 손잡이가 처음부터 정답 위치에 있어도 막는 검사가 없다.
   - 실물 화면과 글자를 그릴 수단이 없는데, 이것이 다음 작업 목록에서 빠졌다.
8. **sheet가 실제 겹침을 놓쳤다.** layoutViolations는 0인데 검토자가 겹침 4건을 보고했다.
9. **검토 방법에 한계가 있다.**
   - 화면 검토자는 lesson.js를 보면서 판단했고, 기준선은 같은 기준으로 검토하지 않았다.
   - 사실 검토는 attacker 하나만 했다.
   - 정답 검산은 가정 값들이 서로 맞는지만 본다. 그래도 실제 오류 1건을 잡았다.
10. **`analyze.py`의 집계에 작은 오류가 있다.** sheet 실행과 python·sed 수정을 세지 못했다.
11. **표본이 작다.** 주제와 경로마다 1회씩만 실행했다.

## 방향 대안

### 대안 A: 문서형 하이브리드
- **내용**
  - 글, 표, 코드, 실물 예시는 agent가 HTML로 쓴다.
  - 수치 모델 그림, 예측 상자, 퀴즈만 검증된 부품으로 넣는다.
- **쓸모없어지는 것**: 장면 엔진, 장면 타입 문법, 그림 필수 계약, 전환 애니메이션 계획.
- **남는 것**: model, layout, check 모델 규칙, digest, 정답 검산, sheet.
- **위험**
  - 문서 부분의 배치 결함
  - 의도 5번(전환 애니메이션)을 잃음
  - 부품과 문서가 만나는 경계의 결함

### 대안 B: 얇은 skill
- **내용**
  - 기준선 HTML 생성에 다섯 가지를 더한다: 진단 결과, 짧은 교수 설계 체크리스트, 작은 보조 스크립트, 두 폭에서 결정적 검사 1회, 대화 속 서술 퀴즈와 map.
- **쓸모없어지는 것**: runtime 패키지 거의 전부. src 7,456줄, 시험 5,319줄.
- **위험**
  - SVG 안의 글자 겹침
  - 수치를 검산할 수단이 약함
  - 수업마다 모양이 다름

### 결정 실험(검수자 제안)
- **0단계**: 기존 3쌍을 블라인드로 판정한다.
- **1단계**: 6주제 × 3팔(현재 skill, 공정 기준선, 얇은 skill) × 2회를 돌린다. 약 $40–50, 1–1.5일.
- **판정 규칙**: 현재 skill의 승률이 65% 이상이면 유지, 50% 이하면 전환, 그 사이면 주제별로 본다.

## 현재 방향을 가장 강하게 옹호하면
- 사용자 의도 2·4·5번(모델 그림, 현대적 UI, 전환)을 항상 지킨다.
- 형식 규칙을 타입과 check로 강제한다.
- 수치를 검산할 수 있다.
- runtime 결함을 한 번 고치면 모든 수업에 적용된다.
- 모바일 배치가 수업마다 같다.
- 학습 이벤트가 구조화된다.
- 수업이 데이터로 남는다.

검수자는 이 장점 대부분이 대안 A의 부품 안에 남는다고 본다. runtime만의 이점은 고정 화면 slide와 전환 애니메이션이고, 그 학습 가치는 잰 적이 없다고 본다.

## 판정
- 현재 방향을 기본 형식으로 계속 키우는 데 반대한다. 확신은 약 65%다.
- 문서형으로 가되, A와 B 중 무엇인지는 공정 비교로 정한다.
- **판정을 뒤집을 증거**
  - 공정 비교에서 현재 skill이 비수치 주제를 포함해 65%를 넘게 이긴다.
  - 얇은 skill이 차단 결함을 꾸준히 남기고, 그것을 고치는 반복 때문에 비용이 현재 skill 이상이 된다.
  - 학습자 데이터가 예측·탐색 장면의 효과를 보여 준다.
  - 사용자가 slide와 전환을 필수 요구로 확정한다.

## 놓치고 있는 것
- 학습 결과를 잰 적이 없다.
- 진단을 시험한 적이 없다. 또 "사다리 한 단 = 절 하나" 규칙 때문에 수업이 개념을 차례로 훑는 데 그친다.
- 주제에 맞는 매체를 고르는 판단이 없다. UI, 코드, 실데이터, 글 중심 주제는 HTML이 매체다.
- 글 분량 상한이 "교과서 한 챕터"와 부딪친다. 본문 음절 수가 기준선의 56–63%다.
- 검증 노력이 runtime 층에만 쓰였다.
- 생성 쪽과 판정 쪽이 같은 설정(opus, effort low)이다.
- claude.ai 경로를 시험하지 않았다. runtime 묶음은 약 3.9 MB다.
