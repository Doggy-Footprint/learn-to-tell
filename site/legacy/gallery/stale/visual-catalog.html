시각 요소 카탈로그

수업 자료에 쓸 수 있는 도표·그래프·인포그래픽 요소 모음. 각 요소의 ID로 스타일 요구를 말하면 된다 (예: "C3 막대를 더 굵게").

표시용 샘플 데이터 — 실제 값 아님버튼·슬라이더는 실제로 동작한다. 애니메이션은 사용자가 조작할 때만 재생된다.

요소 목록

S. 스타일 토큰

모든 요소가 공유하는 색·글자·컨트롤. 색은 하는 일(정체성·크기·방향·상태)로 고른다.

S1

색 역할

쓰임: 계열은 정체성, 순차는 크기, 발산은 기준 대비 방향, 상태는 좋음·나쁨(아이콘·라벨과 함께)

구현: kit CSS 변수 --ltt-* · 페이지 CSS 변수 --s1…--s4, --de

S2

글자 크기

쓰임: 화면의 위계. 큰 숫자는 한 화면에 하나

구현: kit 클래스 ltt-lead ltt-basis ltt-stat ltt-hero

h1 28px알림이 울리면 진짜 장애일까?
h2 19px조건 바꾸기
본문 16px드문 장애의 95%보다 흔한 정상의 5%가 더 많다.
ltt-lead결정 변수: 알림 임계
ltt-basis 12px0.1–20%: 예시용 가정. 서비스마다 다르다.
ltt-stat 40px68/ 100건
ltt-hero 72px16건 / 100건
S3

컨트롤·카드

쓰임: 조작 요소와 카드 틀의 기본 모양

구현: kit 기본 스타일 · 페이지 클래스 sub ghost pill

카드: radius 14px · 1px 선 · 옅은 그림자

A. 핵심 수치

답이 숫자 하나일 때. 차트보다 먼저 고려한다.

A1

큰 숫자 + 카운트업

쓰임: 화면의 핵심 수치 하나를 크게 보이기

구현: kit ltt-hero · d3 transition (페이지 함수 tweenNumber)

16건 / 100건

알림 100건 중 진짜 장애 모델로 계산한 예시

A2

KPI 행 (stat tile)

쓰임: 함께 보는 수치 몇 개를 값·변화·추세로 나란히

구현: kit ltt-stat · d3 SVG 스파크라인 · 상태 색 + ▲▼ 아이콘

A3

전후 비교 숫자

쓰임: 선택 하나를 바꿨을 때 수치가 얼마나 움직이는지

구현: kit ltt-stat · CSS 막대

TTL 10초
5.7
→
TTL 5분
0.2회/분

원본 요청 ▼ 96% 감소

TTL 10초 TTL 5분
A4

범위 숫자

쓰임: 값이 불확실할 때 점 하나 대신 구간으로 말하기

구현: kit ltt-stat · d3 SVG 구간 막대

12–18건불확실

점추정 15건, 가정이 바뀌면 구간도 바뀐다.

A5

미터 (한도 대비)

쓰임: 한도에 얼마나 가까운지, 경고선을 넘었는지

구현: CSS 트랙 (같은 색 계열) · 상태 태그 (아이콘 + 라벨)

64%● 정상
경고 80%

B. 비율·건수

비율을 "100건 중 몇 건"처럼 셀 수 있는 모양으로.

B1

100칸 단위 그림

쓰임: 비율을 건수로 보이기

구현: kit ltt-units ltt-unit ltt-key · 페이지 함수 makeUnits paintUnits

진짜 장애 16오탐 84

B2

사람 아이콘 배열

쓰임: 사람·사용자 단위의 비율을 구체적으로

구현: 인라인 SVG 아이콘 · CSS transition (칸마다 --i 지연)

20명 중 3명 (15%)

B3

비율 막대

쓰임: 한 묶음이 몇 갈래로 나뉘는지 (부분-전체)

구현: 페이지 클래스 vc-bar (kit ltt-bar + 2px 간격) · 들어갈 때만 라벨

응답 100건 기준. 좁은 칸의 값은 범례와 hover로 본다.

B4

건수 흐름 분기 (자연 빈도 나무)

쓰임: 조건부 확률을 "10,000건이 어디로 갈라지나"로 풀기

구현: d3 SVG (d3.linkHorizontal, 선 굵기 ∝ 건수)

알림 · 진짜
알림 · 오탐
알림 없음

울린 알림 = 95 + 495 = 590건, 그중 진짜는 95건(16%). 선 굵기는 건수에 비례한다.

B5

단위 그림 나란히 비교

쓰임: 두 조건의 비율 차이를 같은 틀에서 비교

구현: kit ltt-units 두 개 · 페이지 함수 paintUnits

기저율 1%
16/ 100건
기저율 10%
68/ 100건

같은 탐지율 95% · 오탐률 5%. 차이 +52건.

B6

깔때기

쓰임: 단계마다 얼마나 남는지, 어디서 많이 빠지는지

구현: d3 SVG · 순서형 파랑 (#86b6ef부터 진하게)

B7

건수 흐름 막대

쓰임: 전체가 갈라진 뒤 일부만 다시 모이는 과정을 두 줄 막대로

구현: 페이지 클래스 vc-bar 두 줄 · flex-grow 전환 · 숫자 tween

탐지율 95% · 오탐률 5%. 건수는 반올림.

C. 그래프

값의 관계·추세·분포. hover로 값을 읽고, 핵심 점만 직접 라벨을 단다.

C1

선 그래프 + 현재 값 (sweep)

쓰임: 결정 변수를 움직이면 결과가 곡선 위 어디로 가는지

구현: Plot line ruleX dot tip(pointerX) · 슬라이더 입력마다 다시 그림

C2

누적 영역 (구성 변화)

쓰임: 변수에 따라 전체의 구성(최신·오래됨·miss)이 어떻게 바뀌는지

구현: Plot areaY + lineY(stackY2) 경계선 · 범례 · 한 툴팁에 전 계열

C3

가로 막대 + 강조

쓰임: 선택지 크기 비교, 그중 하나에 시선 모으기

구현: Plot barX text · 강조 1개 + 나머지 회색

C4

그룹 막대

쓰임: 두 선택지를 여러 작업에서 나란히

구현: Plot barY + fx 묶음 · 범례

C5

덤벨 (전 → 후)

쓰임: 항목별 변경 전후 차이

구현: Plot link dot · 한 색의 두 단계

변경 전변경 후
C6

분포 + 분위수

쓰임: 평균 하나로 가려지는 꼬리(p95) 보이기

구현: Plot rectY(binX) ruleX · d3 randomLcg 고정 시드 표본

C7

산점도 + 효율 경계

쓰임: 두 목표의 trade-off, 더 나은 선택지가 없는 경계

구현: Plot dot line tip(pointer) · 계열 3개 상한

C8

히트맵 (변수 두 개)

쓰임: 두 변수 조합마다 결과가 어떤지 한눈에

구현: Plot cell · 순차 파랑 + 색 범례

C9

작은 그림 여러 개 (small multiples)

쓰임: 조건 하나를 바꾼 여러 판을 같은 축으로 비교

구현: Plot fx 분할 · y축 공유

C10

기준선 대비 막대 (발산)

쓰임: 목표보다 나은지·나쁜지를 방향으로

구현: Plot barX ruleX(0) · 파랑 ↔ 빨강

목표보다 빠름목표보다 느림

D. 흐름·상태

순서와 상태가 핵심인 비수치 자료. 한 단계씩 진행하고, 끝난 화면만으로도 읽힌다.

D1

시퀀스 다이어그램

쓰임: 누가 누구에게 무엇을 보냈는지 시간 순서로, 유실 지점까지

구현: d3 SVG · stroke-dashoffset 전환으로 현재 메시지 그리기

D2

상태 머신

쓰임: 어떤 상태에서 어떤 사건이 가능한지, 불가능한 전이는 무엇인지

구현: d3 SVG · 이벤트 버튼 · 색 전환

D3

타임라인 (Gantt)

쓰임: 동시에 실행되는 작업의 시작·끝과 총 소요 시간

구현: d3 SVG · 재생 시 막대가 시간에 맞춰 자람 + 재생 헤드

성공✕ 실패
D4

파이프라인 블록

쓰임: 유입량을 올리면 어느 단계가 먼저 막히는지 (병목)

구현: HTML 블록 · CSS 대기열 막대 · 숫자 tween

처리량 = min(들어온 양, 단계 용량). 넘치는 만큼 대기열이 초마다 쌓이고, 가장 빨리 쌓이는 단계가 가장 큰 병목이다. 앞 단계가 막히면 뒤 단계에는 그만큼만 들어간다.

D5

결정 나무

쓰임: 질문 몇 개로 선택지가 갈리는 길 보이기

구현: d3 SVG · 답 버튼으로 경로 강조

D6

구성도 + 요청 경로

쓰임: 요청 종류마다 어느 구성 요소를 어떤 순서로 지나가는지

구현: d3 SVG · 버튼 hover/클릭으로 경로 강조, 순서 번호

E. 비교·결정

선택지를 조건과 함께 비교한다. 조건을 바꾸면 추천이 바뀌는 것을 보인다.

E1

조건 토글 비교표

쓰임: 어떤 조건이 켜지면 추천이 바뀌는지

구현: HTML 표 · ✓/△/✗ 기호 + 라벨 · 추천 열 배경 전환

추천 표시용 샘플 판정

규칙: ✗가 있으면 제외 → △가 적은 쪽 → 같으면 단순한 쪽(A안).

E2

사례 카드 (활용·주의·대안)

쓰임: 유리한 예와 실패 예를 함께 두기

구현: kit ltt-tag ltt-units ltt-stat

E3

코드 변형 비교

쓰임: 같은 일을 하는 코드 변형과 달라진 줄

구현: 페이지 함수 (줄 단위 LCS diff, 키워드 색) · 탭 버튼

E4

2×2 사분면

쓰임: 판단 두 개(비용·효과)로 선택지 묶기

구현: Plot dot text ruleX/ruleY · hover

E5

조건 대칭 카드

쓰임: 핵심 결정의 찬성·반대 조건을 같은 무게로

구현: CSS grid 3열 (좌·갈림 조건·우)

짧은 TTL이 낫다

  • 데이터가 자주 바뀐다
  • 오래된 값의 비용이 크다
  • 원본에 여유가 있다
갈림 조건변경 주기 대비
오래된 값의 비용

긴 TTL이 낫다

  • 데이터가 드물게 바뀐다
  • 오래된 값을 허용한다
  • 원본 부하가 민감하다

F. 예측 입력

결과를 보기 전에 예측을 받는다. 확정한 첫 예측은 바꿀 수 없다.

F1

슬라이더 예측 → 단위 그림 공개

쓰임: 비율 예측을 그림으로 받고, 모델 값과 겹쳐 보이기

구현: kit ltt-units ltt-hero · LTT.record("predict") · 칸별 지연 공개

알림 100건 중 진짜 장애는 몇 건? 기저율 1% · 탐지율 95% · 오탐률 5%

50건 / 100건
모델로 계산한 예시

진짜 장애오탐

F2

선택지 카드 예측

쓰임: 개념적 예측(어느 쪽일까)을 고르게 하기

구현: 버튼 카드 · 확정 후 정답·오답 표시 + 설명 등장

기저율 1%, 탐지율 95%, 오탐률 5%. 알림이 울렸을 때 진짜 장애일 확률은?

F3

수직선 예측 vs 실제

쓰임: 값 하나를 짚게 하고 실제와의 거리 보이기

구현: d3 SVG (클릭·방향키로 위치) · 실제 표시 전환

기저율을 10%로 올리면 알림 100건 중 진짜는?

선 위를 클릭해 예측을 놓는다.

F4

순서 맞히기

쓰임: 크기·순서에 대한 감각 확인

구현: 버튼 목록 · 공개 시 FLIP 이동

지연이 짧은 것부터 차례로 누르기

대략적 규모 순서. 하드웨어마다 다르다.

F5

구간 예측

쓰임: 확신 정도까지 함께 받기 (구간 폭)

구현: 슬라이더 두 개 · d3 SVG 구간 · 공개 시 실제 값 표시

기저율 1%일 때 알림 100건 중 진짜 장애, 80% 확신 구간은?

G. 주석·보조

근거·불확실성·검증 상태를 표시하는 작은 요소들.

G1

태그

쓰임: 수치의 성격과 검증 상태 표시

구현: kit ltt-tag (good bad warn)

모델로 계산한 예시불확실미검증✗ 검증 실패
활용주의대안

G2

hover 설명

쓰임: 본문은 짧게, 용어 설명은 마우스를 올릴 때

구현: kit data-tip 속성

알림의 정밀도는 기저율에 크게 좌우된다.

G3

차트 주석 (callout)

쓰임: 곡선에서 봐야 할 한 점을 글로 짚기

구현: Plot arrow text dot

G4

범례

쓰임: 계열 정체성. 막대·영역은 사각형, 선은 선, 점은 점

구현: kit ltt-key · 페이지 클래스 key-line key-dot

최신 적중오래된 적중miss
적중률오래된 비율
변경 전변경 후
✓ 적합△ 주의✗ 피함
G5

표로 보기

쓰임: 차트 값을 hover 없이도 읽는 대체 경로

구현: Plot barY · <details> 표 (tabular-nums)

표로 보기
G6

기대값 대조 패널

쓰임: 모델 값이 손계산 기대값과 맞는지 페이지가 스스로 확인

구현: kit LTT.expect (불일치 시 서버에 기록)

오른쪽 아래에 고정된 "기대값 대조" 패널이 이 요소다. 이 페이지는 예시로 두 값을 대조한다.

스타일 요구는 요소 ID와 함께 대화로 알려 주세요.
