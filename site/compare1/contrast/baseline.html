글자색·배경색 대비비, 숫자로 판단하기

설정 화면의 보조 텍스트(설명 문구, 힌트, 부가 정보) 색을 고를 때 "이 회색이 WCAG AA/AAA를 넘는가?"를 감이 아니라 계산으로 판단하는 법을 익힙니다. 약 20분 분량이고, 마지막에 퀴즈가 있습니다.

1. 판단 기준 한 줄 요약

두 색의 상대 휘도 L을 구해 (밝은 L + 0.05) / (어두운 L + 0.05)를 계산한다. 결과(1~21)가 일반 텍스트는 AA 4.5 이상, AAA 7 이상, 큰 텍스트는 AA 3 이상, AAA 4.5 이상이면 통과다. 반올림해서 통과시키지 않는다(4.49는 탈락).

보조 텍스트는 대개 14~16px 일반 굵기이므로 "일반 텍스트" 기준(AA 4.5:1)이 적용됩니다. "보조라서 덜 중요하니 기준이 낮다"는 규정은 없습니다. 예외는 비활성(disabled) 컨트롤의 텍스트, 순수 장식, 로고뿐입니다.

2. 왜 RGB 평균이 아니라 '상대 휘도'인가

사람 눈이 느끼는 밝기는 두 가지 이유로 #RRGGBB 값과 비례하지 않습니다.

(1) 감마: 코드 값은 빛의 양이 아니다

sRGB 값 128(#808080)은 빛 에너지로 보면 255의 절반이 아니라 약 22%입니다. sRGB는 어두운 영역에 코드 값을 더 많이 배정하도록 감마 곡선으로 인코딩되어 있기 때문입니다. 그래서 계산 전에 먼저 선형화(linearize)합니다.

c = 채널값 / 255 (0~1로 정규화) c ≤ 0.04045 이면 lin = c / 12.92 그 외 lin = ((c + 0.055) / 1.055) ^ 2.4

WCAG 2.x 원문은 경계값을 0.03928로 적고 있지만, 8비트 색상에서는 두 값 사이에 해당하는 채널값이 없어 결과가 같습니다.

(2) 채널별 민감도: 초록이 압도적으로 밝다

눈은 초록에 가장 민감하고 파랑에 가장 둔합니다. 선형화한 R, G, B에 가중치를 곱해 더한 값이 상대 휘도 L(0=검정, 1=흰색)입니다.

L = 0.2126 × R_lin + 0.7152 × G_lin + 0.0722 × B_lin
직관 확인: 같은 "최대 채널값"이라도 휘도는 크게 다릅니다.
색상대 휘도 L흰 배경 대비비

순수 파랑 #0000FF는 흰 배경에서 8:1을 넘지만, 순수 초록 #00FF00은 1.4:1에 불과합니다. "진해 보이는 색"과 "어두운 색"은 다릅니다.

3. 대비비 공식과 계산 따라 하기

대비비 = (L_밝은 + 0.05) / (L_어두운 + 0.05)
  • 항상 밝은 쪽을 분자에 둡니다. 그래서 글자/배경을 뒤바꿔도 값이 같습니다.
  • +0.05는 화면 반사광(flare)을 반영한 보정입니다. 덕분에 검정(L=0)으로 나누는 일이 없고, 최댓값은 흰/검 조합의 1.05/0.05 = 21입니다.
  • 범위는 1:1(같은 색) ~ 21:1(흰/검).

손으로 계산해 보기: #767676 on #FFFFFF

0x76 = 118 → c = 118/255 = 0.4627 lin = ((0.4627 + 0.055) / 1.055)^2.4 = 0.4907^2.4 ≈ 0.1812 회색이므로 R=G=B → L = 0.1812 × (0.2126+0.7152+0.0722) = 0.1812 흰색 L = 1 대비비 = (1 + 0.05) / (0.1812 + 0.05) = 1.05 / 0.2312 ≈ 4.54 → AA 일반 텍스트 통과

한 단계 밝은 #777777은 4.48로 탈락합니다. 흰 배경에서 AA를 통과하는 가장 밝은 회색이 #767676이라 자주 인용되는 값입니다.

4. AA / AAA 기준표와 '큰 텍스트'의 정의

대상AAAAAWCAG 조항
일반 텍스트4.5 : 17 : 11.4.3 / 1.4.6
큰 텍스트3 : 14.5 : 11.4.3 / 1.4.6
UI 구성요소 경계·아이콘·포커스 표시 등 비텍스트3 : 1(별도 기준 없음)1.4.11
비활성 컨트롤 텍스트, 장식, 로고요구 없음1.4.3 예외

"큰 텍스트"란

  • 18pt 이상(CSS로 약 24px) 일반 굵기, 또는
  • 14pt 이상(약 18.66px) 굵게(bold, 보통 font-weight:700).

1pt = 1.333px입니다. 설정 화면 보조 텍스트(12~16px, 400)는 거의 항상 큰 텍스트가 아니므로 4.5:1을 기준으로 잡으세요. font-weight:600은 서체에 따라 bold로 보기 애매하므로 보수적으로 일반 텍스트로 취급하는 편이 안전합니다.

6. 실습 2: 회색 슬라이더로 경계 찾기

7. 보조 텍스트에서 자주 틀리는 지점

(1) 투명도(opacity / rgba)로 만든 회색

color: rgba(0,0,0,.45)나 opacity:.6는 "실제로 화면에 칠해진 색"으로 합성한 뒤 계산해야 합니다. 합성은 sRGB 값 단위로 결과 = α × 글자 + (1−α) × 배경(브라우저 기본 동작). 같은 rgba라도 배경이 바뀌면 대비비가 바뀝니다. 특히 다크 모드에서 같은 토큰을 재사용하면 깨지기 쉽습니다.

(2) 배경이 하나가 아닐 때

설정 화면은 페이지 배경, 카드 배경, hover 행 배경, 선택된 행 배경이 서로 다릅니다. 보조 텍스트가 놓일 수 있는 가장 불리한 배경(대개 hover/selected 상태의 연회색)에서 4.5를 넘어야 합니다.

(3) placeholder와 힌트 텍스트

입력란 placeholder도 텍스트이므로 4.5:1 대상입니다. 기본 브라우저 placeholder 색이 연한 경우가 많으니 직접 지정하세요.

(4) disabled 예외의 오용

예외는 "실제로 비활성인 컨트롤"의 텍스트에만 적용됩니다. 활성 상태의 설명 문구를 흐리게 처리하면서 이 예외를 근거로 삼을 수는 없습니다.

(5) 반올림

도구가 "4.5:1"로 반올림해 보여주더라도 실제 값이 4.48이면 탈락입니다. 이 페이지의 계산기는 소수 둘째 자리까지 내림 없이 비교합니다.

(6) 대비비는 필요조건이지 충분조건이 아니다

WCAG 2.x 공식은 얇은 서체, 아주 작은 크기, 다크 모드의 밝은 글자에서 실제 가독성을 과대·과소평가할 때가 있습니다. 차세대 지표(APCA, WCAG 3 초안)가 논의되고 있지만, 현재 규정 준수 판단은 WCAG 2.x의 이 공식이 기준입니다.

8. 확인 퀴즈

객관식은 고르면 바로 해설이 나옵니다. 서술형은 먼저 직접 써 본 뒤 모범 답안과 비교하세요.

9. 설정 화면 적용 체크리스트

  1. 보조 텍스트의 실제 크기·굵기를 확인 → 24px 미만 일반 굵기면 기준은 AA 4.5 / AAA 7.
  2. 보조 텍스트가 놓이는 모든 배경(페이지, 카드, hover, selected, 다크 모드)을 나열.
  3. rgba·opacity를 쓴다면 각 배경과 합성한 최종 색으로 계산.
  4. 가장 낮은 대비비가 목표 기준 이상인지 확인(반올림 금지).
  5. 목표가 AA라도 여유를 두고 4.6~5 이상을 고르면 브랜드 배경 미세 조정에 덜 취약.
  6. 아이콘·토글 테두리 등 비텍스트 요소는 별도로 3:1(1.4.11) 확인.

참고 수치(흰 배경): #767676 4.54(AA 최소), #595959 7.00(AAA 최소), #9CA3AF 약 2.5(탈락), #6B7280 약 4.8(AA). 단, 같은 #6B7280도 연회색 #F3F4F6 위에서는 약 4.39로 AA 미달입니다.
