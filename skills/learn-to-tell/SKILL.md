# Learn to Tell

목표는 숙련이 아니다. 사용자가 (1) 적절한 질문을 하고 (2) agent의 도움으로 결정 변수를 고르고 (3) 그 선택의 의미를 설명할 수 있게 하는 것이다. tacit knowledge는 다루지 않는다.

경로: `<skill>` = 이 skill의 base directory, `<home>` = `$LTT_HOME`(기본 `~/.learn-to-tell`), lesson id = `YYYYMMDD-<kebab-slug>`, 수업 폴더 = `<home>/lessons/<id>/`.

## 0. 시작

- claude.ai(웹·모바일)처럼 `<home>`과 로컬 서버가 없으면 `<skill>/standalone.md`를 먼저 읽는다.
- agent가 제안할 때는 지식 차이와 그것이 막는 결정을 한 문장으로 말하고, 진단만 받을지 학습까지 할지 묻는다.
- 학습은 작업 세션에서 `/fork`한 세션에서 한다. fork한 세션이 아니면 `/fork` 후 `/learn-to-tell <주제>`를 실행하라고 안내하고 멈춘다. 진단만은 지금 세션에서 해도 된다.
- 작업 세션의 context가 100k tokens 이상으로 보이면 새 세션을 권하고, 작업 맥락(목표, 막힌 결정, 이미 정한 것)을 `<home>/lessons/<id>/context.md`로 남긴다.
- `<home>/background.md`가 있으면 읽고 사다리의 시작 단, 예시, 풀어 줄 용어를 맞춘다. 새로 안 배경은 `- <YYYY-MM-DD> <사실 한 줄> (출처: 진단 | 대화 | lessons/<id>)`로 덧붙인다(제목 `# Learn to Tell background`).

## 1. 진단 (대화)

- 상황에 필요한 개념으로 낮은 수준부터 3–5단짜리 개념 사다리를 세운다. 낯선 용어로 시작하지 않는다.
- 중간 단부터 개념의 뜻, 이 상황에서 필요한 이유, 한 줄 예시를 보이고 "알고 있음 / 애매함 / 아예 모름"을 고르게 한다. 알고 있음·애매함이면 위 단, 아예 모름이면 아래 단으로 간다. 질문은 확인 퀴즈를 포함해 최대 5개다.
- 아는 개념 바로 위의 모르는 개념이 학습 수준이다. 맨 위 단까지 알면 퀴즈로 확인하고 통과하면 학습 없이 결과만 기록한다. 맨 아래 단도 모르면 한 단을 더 내린다. 질문 상한에 닿으면 그때의 맨 아래 단이 학습 수준이다.
- 애매함인 개념은 수업에 일부 넣는다. 핵심 결정 변수에 알고 있음이라 답하면 퀴즈 하나로 확인하고, 틀리면 오개념으로 적어 hook 소재로 쓴다.
- 되물으면 정답을 대신 말하지 않고 짧게 답한 뒤 같은 질문을 다시 받는다. "아예 모름"은 정당한 답이고, 진단 결과는 가설이다.

## 2. 학습 목표 확인

- 진단 뒤 한 메시지로 제안한다: 학습 목표 1–3줄("이 수업을 마치면 …를 설명하고 고를 수 있다"), 다룰 결정 변수, 다루지 않을 것, 예상 장면 수. 사용자가 한 번 답하면 확정한다(고쳐 달라면 한 번 반영하고 진행한다).
- 범위는 결정 변수에서 출발해 그것을 설명하는 데 필요한 교과서 기본기를 교과서 순서로 거슬러 올라간다. 분량은 대략 교과서 한 챕터, 기본 8–10장면(12장면 상한은 lint가 막는다. 넘기려면 `budget`에 이유를 적는다).
- 결정 변수는 개념 이름이 아니라 선택지·영향·필요 정보·실패 조건으로 다룬다. 결정 변수마다 예측(predict) → 조작(play 또는 figure) → recall 하나.
- 조작해서 관찰할 필요가 없으면 simple 경로: 대화 안의 짧은 자료와 서술 퀴즈로 하고 §3을 건너뛴다.

## 3. 수업

자료는 사용자가 혼자 읽고 이해할 수 있어야 하고, 장면마다 그림 하나가 메커니즘을 움직여 보인다. 아래 순서를 한 번 지나가고 되돌아가지 않는다.

1. 한 응답에서 함께 Read: `<skill>/kit/API.md`, `<skill>/look/look.md`, `<skill>/look/board.jpg`. look.md 색인에서 개념 구조와 움직임이 맞는 shot 카드 2장(`<skill>/look/shots/sNN.jpg`)도 같이 읽는다. `LTT.draw`를 쓸 장면이 있을 때만 `<skill>/kit/api/draw.md`.
2. `<home>/lessons/<id>/outline.md`(2,500자 안팎)를 쓴다:
   - 매체·테마·주 그림(수업 전체를 관통하는 그림 하나, 장면마다 단계적으로 바꿔 보인다)
   - 장면마다 한 줄: `type · 주장 제목 · 부품 · 움직임(무엇이 어디로) · 기대 화면`
   - `## 주장`: 결정 변수에 관한 주장(공식·범위·비교 판정)과 근거
   - `## 모델`: 수치 모델이 있으면 공식, 상수와 출처, 계산 지점(label과 입력값)
3. 같은 응답에서 검토 서브에이전트를 background로 띄운다(아래 "검토").
4. `lesson.html`을 한 번에 Write한다(`lesson: "<id>"`, `goal`은 §2에서 확정한 문장). `LTT.expect`의 기대값 자리는 비워 둔다.
5. `node <skill>/server/check.mjs <id>`를 실행한다. "고칠 것"을 Edit 한 묶음으로 고치고, 출력에 나온 sheet(움직이는 장면만)를 Read해 look.md의 눈 기준으로 본다. 정적 장면은 보지 않는다(kit이 보장한다).
6. 검토 결과(틀린 주장, 기대값)와 sheet에서 본 것을 Edit 한 묶음으로 반영하고 `check.mjs <id> --scenes <고친 장면>`으로 다시 잰다. check는 최대 3회. 3회째에도 남은 것은 `result.md`에 적는다.
7. `check.mjs <id> --cover`로 대표 이미지를 남긴다(수업 목록 grid에 쓰인다).
8. 서버를 백그라운드로 띄운다: `node <skill>/server/server.mjs`(실행 중이면 재사용, 포트 `LTT_PORT` 기본 47823). `http://127.0.0.1:47823/lessons/<id>/lesson.html`을 안내한다.
9. 사용자가 다 봤다고 하면 `events.jsonl`의 `predict`, `term`, `recall`, `goal`, `expect-mismatch`를 읽는다. 여러 번 연 용어와 열지 않은 recall은 §4에서 묻는다.

하지 않는다:
- kit 소스(`kit/*.js`), `server/*.mjs`, gallery를 읽거나 grep하지 않는다. 문서에 없는 것은 있는 부품으로 대신하고 `result.md`의 "kit 후보"에 적는다.
- `lesson.html`을 다시 통째로 쓰거나 python·sed로 고치지 않는다(Edit만). 자기가 쓴 `lesson.html`을 다시 Read하지 않는다.
- 오류를 피하려고 상한이나 판정을 우회하지 않는다. 글을 줄이거나 장면을 나눈다.

### 검토

- 서브에이전트 1개, `model: "sonnet"`. 줄 것: outline.md의 `## 주장`과 `## 모델` 절만(lesson.html과 모델 코드는 주지 않는다). 프롬프트: "각 주장이 맞는지, 빠진 조건과 출처 오류를 찾아 고친 문장을 제시하라. `## 모델`이 있으면 계산 지점마다 기대값을 직접 계산하라(코드 실행 가능). 맞는 것은 맞다고만 쓴다."
- 기대값은 `LTT.expect(label, actual, expected, { tol })`로 넣는다. 불일치가 나면 먼저 손으로 다시 계산하고, 모델에 맞춰 기대값을 고치지 않는다. 한 번 고친 뒤에도 남으면 그 부분을 빼거나 "검증 실패"로 표시하고 사용자에게 알린다.
- 서브에이전트를 쓸 수 없으면 기대값을 모델 코드보다 먼저 직접 적고, 결정 변수에 관한 주장에 "미검증"을 단다.
- 슬라이더는 실사용 범위만 움직이고 범위·상수에 근거를 단다. 근거가 약하면 "불확실"이라고 쓴다.

## 4. 이해 확인 (대화)

- 서술 퀴즈로 질문 만들기와 선택·의미 설명을 확인한다. 평가 기준은 답을 받기 전에 정하고 보여 주지 않는다.
- 판정은 pass / fail / skipped다. 제출된 답은 skipped로 처리하지 않는다. pass는 "이번 상황과 도움 수준에서의 관찰"이지 능력 판정이 아니고, 도움을 받은 수행은 따로 표시한다.
- 피드백은 관찰 근거 중심으로 하고 사실 판정과 정서적 지지를 분리한다. 핵심 결정 1건은 찬성·반대 조건을 대칭적으로 확인한다.

## 5. 작업 복귀

`<home>/lessons/<id>/result.md`를 항상 쓴다. frontmatter는 수업 목록 페이지(`http://127.0.0.1:47823/`)가 읽는다.

```markdown
---
lesson: <id>
date: <YYYY-MM-DD>
title: <수업 제목>
goal: <확정한 학습 목표 한 줄>
decision: <이번 결정 또는 보류, 한 줄>
---
# <주제> (<id>)
- 작업: <원래 작업 한 줄>
- 진단: <사다리 단별 응답과 학습 수준>
- 이번 결정: <선택 또는 보류 이유>
- 선택을 바꾸는 조건: <조건>
- agent에게 할 질문: <질문들>
- 퀴즈: <문항별 pass/fail/skipped, 도움 여부>
- 미룬 범위: <다음 수업 후보>
- kit 후보: <문서에 없어 대신한 것, 없으면 생략>
- 생성 비용: lesson.html <바이트>, 장면 <n>(움직임 <n>), check <n>회, 남은 지적 <없으면 0>, 시작 <HH:MM> → 공개 <HH:MM>
```

그다음 ListAgents로 원래 작업 세션을 찾아 SendMessage로 요약과 `result.md` 경로를 보낸다. 찾을 수 없으면 사용자에게 경로를 알려 원래 세션에 전달하게 한다. 지난 수업은 `http://127.0.0.1:47823/`에서 대표 이미지 grid로 다시 본다.
