      키가 바뀌면 서버는 다른 요청으로 본다. 키가 없는 것과 같다.

      주의처리 중에 같은 키가 또 오면

      처리 결과를 저장하기 전에 같은 키가 또 오면 두 번 처리될 수 있다.

      처리 중인 키를 먼저 표시해 둔다. IETF Idempotency-Key 초안은 이때 409 Conflict 응답을 권한다(SHOULD). 이 시뮬레이션 밖의 경우다.

      근거

      • 서버는 키와 첫 처리 결과를 저장해 같은 키의 재요청에는 저장된 결과를 돌려준다(Stripe API v1 방식. IETF Idempotency-Key 헤더 초안도 같은 개념이며 표준으로 확정되지는 않았다).
      • Stripe API v1은 24시간 이상 지난 키를 자동으로 정리할 수 있어, 그 뒤 같은 키로 재시도하면 새 요청으로 처리된다(API v2는 30일).
      • Stripe API v1은 같은 키로 다른 파라미터를 보내면 오류를 돌려준다.
      • HTTP 명세(RFC 9110 9.2.2)에서 PUT, DELETE와 GET 같은 안전한 메서드는 멱등이고, POST는 아니다.

      출처: docs.stripe.com/api/idempotent_requests · docs.stripe.com/api-v2-overview#idempotency · draft-ietf-httpapi-idempotency-key-header-07 · RFC 9110 §9.2.2
