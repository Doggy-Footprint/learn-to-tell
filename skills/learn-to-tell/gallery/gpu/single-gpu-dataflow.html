GPU 연산기가 2배 빨라지면 글 생성도 2배 빨라질까?

작업: 모델을 GPU 한 장에 올려 서빙하려는데 어떤 GPU 투자가 생성 속도를 올리는지 모른다. 결정 변수: 토큰 하나당 시간을 정하는 것이 메모리 대역폭인지 연산 속도인지. 모든 계산은 이상적 상한(roofline)이다

먼저 예측

모델은 큰 숫자 표(가중치)다. 토큰 하나를 만들 때마다 이 표 전체를 한 번 읽는다. 8B 모델(BF16, 표 16 GB)을 GPU 한 장에서 사용자 1명에게 돌릴 때, 연산기만 2배 빠른 GPU로 바꾸면 생성 속도는 몇 배가 될까?

조건을 바꿔 보기 모델로 계산한 예시

0tok/s (전체)

사용자 1명이 체감하는 속도: tok/s

표를 읽는 시간 (HBM → 연산기)
계산하는 시간

토큰당 시간 = max(가중치 바이트 / 대역폭, 2 × 파라미터 × batch / 연산 속도). 하드웨어는 H100 SXM: HBM3 약 3.35 TB/s, BF16 dense 약 989 TFLOPS (NVIDIA H100 데이터시트, 작성 시 원문 재확인 안 함 불확실). BF16은 파라미터당 2바이트, 토큰당 파라미터당 곱셈·덧셈 2회로 단순화했다. 크기 범위 1–34B는 가중치가 80 GB HBM의 85% 이내인 구간이다. KV cache·커널 오버헤드·실제 대역폭 효율은 무시했다.

표는 어떻게 움직이나

패킷 수와 속도는 연출이다. L2 캐시는 가중치를 한 번 통과시킬 뿐 담아 두고 재사용하지 못한다고 단순화했다 불확실.

활용과 주의

활용 서버는 사용자를 묶어 같은 읽기로 여러 토큰을 만든다. 같은 GPU에서 처리량이 batch에 거의 비례해 늘다가 약 295에서 꺾인다.
주의 batch를 키워도 한 사람이 받는 속도는 오르지 않는다. 295를 넘으면 오히려 느려진다.
주의 batch마다 대화 기록 저장 공간(KV cache)이 필요해 무한히 키울 수 없다. single-gpu-transformer 페이지에서 다룬다.

한 줄 정리: 글 생성은 표를 읽는 속도에 묶여 있으니, 연산기보다 대역폭이나 batch가 답이다.
