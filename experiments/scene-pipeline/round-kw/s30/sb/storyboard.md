# 스토리보드 · 소스→토큰→AST→바이트코드 (hook)

대상: 컴파일러 입문 개발자 · 결정: 컴파일 단계 구분 · 매체: 터미널 출력

## 독자가 스스로 말할 한 문장
"컴파일러는 글자를 단어(토큰)로 끊고, 단어를 묶어 구조(AST)를 만들고, 구조를 실행 순서(바이트코드)로 펴는데, `4 * 2`가 먼저라는 결정은 토큰이 아니라 AST 단계에서 내려진다."

## 인과 사슬
1. 소스는 글자 나열일 뿐이다 → 렉서가 공백·기호 경계로 끊어 종류가 붙은 토큰 열을 만든다. (구조 정보 없음, 순서만 있음)
2. 토큰 열은 평평하다 → 파서가 연산자 우선순위 규칙으로 묶어 트리(AST)를 만든다. `*`가 `+`보다 강하게 묶인다.
3. 트리는 중첩이고 CPU/VM은 직선으로 실행한다 → 코드 생성이 트리를 후위 순회해 스택 명령 열로 편다.
4. 결과: 묶음 결정은 2단계에서 한 번만 일어나고, 3단계는 그 결정을 순서로 옮길 뿐이다.

## 쓸 예시 (한 줄 소스, 전 단계 공통)
`x = 3 + 4 * 2`
- 소스: 공백 포함 13글자.
- 토큰 7개: IDENT(x) EQ NUM(3) PLUS NUM(4) STAR NUM(2). 공백은 버려진다.
- AST: Assign(x, Add(3, Mul(4, 2))) — 노드 6개(Assign, x, Add, 3, Mul, 4, 2 중 리프 x·3·4·2 = 4개, 내부 Assign·Add·Mul = 3개 → 합 7개).
- 바이트코드 6개: PUSH 3 · PUSH 4 · PUSH 2 · MUL · ADD · STORE x.

## 화면에 꼭 보일 것
- 같은 식이 네 모습(글자 → 토큰 열 → 트리 → 명령 열)으로 바뀌는 흐름과 각 단계 이름.
- 단계 사이에서 사라지는 것(공백)과 새로 생기는 것(종류 태그 → 묶음 → 순서).
- 강조점 하나: `4 * 2`가 묶이는 순간(토큰→AST 경계).

## 사실 점검표 (손 계산)
- 값: 4*2=8, 3+8=11. 만약 `+`를 먼저 묶으면 (3+4)*2=14 — 다른 프로그램이다.
- 토큰 수 7, 바이트코드 6줄(대입 포함). 토큰 수 ≠ 명령 수, 식을 바꾸면 달라진다.
- 후위 순회 순서: 3, 4, 2, MUL, ADD, STORE (자식 먼저, 연산자 나중). 전위가 아니다.
- 스택 깊이 추적: PUSH3→1, PUSH4→2, PUSH2→3, MUL→2(값 8), ADD→1(값 11), STORE→0. 최대 깊이 3, 끝나면 0.
- MUL의 피연산자는 4와 2이지 3이 아니다. ADD는 3과 MUL 결과 8을 받는다.
- 토큰 열에서 `3`과 `+`는 `4`와 `*`보다 앞에 있지만 먼저 실행되지 않는다. 읽는 순서 ≠ 실행 순서.
- 바이트코드 명령 이름(PUSH/MUL/ADD/STORE)은 가상의 스택 VM 표기. 실제 VM마다 이름이 다르다고 한 줄 밝힌다.

## 흔한 오해와 깨는 순간
- 오해: "토큰으로 쪼개면 이미 구조가 잡힌 것이다 / 컴파일은 왼쪽에서 오른쪽으로 번역하는 것이다."
- 깨는 순간: 토큰 열은 `3 + 4 * 2`가 (3+4)*2로도 3+(4*2)로도 읽히는 평평한 줄임을 보인 직후, AST에서 `*` 아래로만 4와 2가 매달리고 바이트코드에서 MUL이 ADD보다 앞에 나오는 것을 보게 한다.

## 비트 (독자가 알아차릴 것)
1. 훅: 터미널에 `x = 3 + 4 * 2`가 놓이고 "결과는 11, 14가 아닌 이유는 어디서 정해졌나?"가 던져진다 → 컴파일에는 눈에 보이지 않는 중간 단계들이 있다.
2. 토큰: 13글자가 7개의 종류 붙은 토큰으로 끊긴다 → 공백은 사라지고, 각 조각이 무엇인지만 알게 됐다.
3. 토큰 열의 모호함: 같은 7개로 묶는 방법이 둘이다 → 토큰 단계에는 "누가 먼저"가 없다.
4. AST: `*`가 4·2를 먼저 묶고 `+`가 3과 그 결과를 묶는다 → 우선순위 결정은 여기서 한 번 일어난다.
5. 바이트코드: 트리가 후위로 펴져 6줄이 되고 스택이 1→2→3→2→1→0으로 오르내린다 → 트리가 직선 실행 순서가 되며, 8이 먼저 나오고 11이 나중이다.
6. 회수: 네 모습을 나란히 놓고 "묶음은 AST, 순서는 바이트코드"를 단계 이름과 함께 되짚는다 → 단계마다 답하는 질문이 다르다(무슨 단어? 어떻게 묶임? 무슨 순서?).
