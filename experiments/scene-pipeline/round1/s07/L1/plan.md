# 제작 계획 · fan-out과 p99 꼬리 지연 (sweep, terminal 테마, 터미널·대시보드)

공통 모델(모든 구성안): 백엔드 호출 지연은 독립·동일 분포. 로그정규 가정(p50 = 10 ms, p99 = 100 ms, σ = ln10 / 2.326 ≈ 0.99, 가정이라고 `basis`에 밝힘).
느린 요청 비율 P(N) = 1 − 0.99ᴺ, 요청 지연 = max(호출 지연), 요청 분포 F(t)ᴺ. 병렬 호출만 다룬다(직렬 합과 섞지 않음).
손 계산 기대값(`LTT.expect`): P(1)=0.01, P(10)=0.0956, P(50)=0.395, P(100)=0.634. 요청 p50/p99(ms, 로그정규 z값으로 손 계산): N=10 → 약 44 / 213, N=100 → 약 114 / 397.

## 구성안

### c1 · 병렬 호출 레인 + 비율 곡선 (뼈대: 타임라인의 max)
- 배치: 좌우 분할. 왼쪽 큰 칸은 요청 1개의 호출 레인(가로 막대 N줄, 시간축 0–400 ms, 100 ms 꼬리선 점선). 오른쪽은 위에 큰 수치 "느린 요청 63%", 아래에 P(N) 곡선(x = N 로그축, 점이 곡선 위를 움직임).
- 움직임과 조작: `LTT.sweep` 손잡이 N(`steps`: 1, 10, 50, 100)이 주(主). 손잡이를 놓아 두면 레인이 5초 주기로 새 표본을 다시 뽑고(자동 재생), 가장 긴 막대 끝에서 "요청 완료" 세로선이 내려온다.
- 비트: ① N=1은 막대 한 줄, 완료선 = 그 막대. ② N=10 이상은 막대가 늘고 완료선이 가장 긴 막대에 걸린다(그 막대만 `--ltt-bad`). ③–④ 곡선 점이 9.6 → 39.5 → 63.4%로 오르고 레인 대부분에 꼬리 막대가 보인다. ⑤ 곡선 오른쪽에 "N=100: 요청 p99 ← 백엔드 p99.99" 주석.
- 실패 위험: N=100 레인이 얇아져 읽기 어렵다(한 줄 3px 이하면 막대가 뭉개짐). 레인을 짧은 점 줄로 줄이는 대신 완료선과 꼬리 막대 강조에 의존.

### c2 · 고정된 백엔드 분포 → 이동하는 요청 분포 (뼈대: 분포의 변환 F(t)ᴺ)
- 배치: 위아래 겹침, 같은 시간축(0–500 ms, 로그 또는 선형 고정). 위 패널 "백엔드 1개"는 N과 무관하게 한 픽셀도 안 바뀌고 p50 10 / p99 100 표식만 있다. 아래 패널 "요청 1개 = 최댓값"은 N에 따라 봉우리가 오른쪽으로 밀리며 100 ms 선 오른쪽 면적(느린 비율)이 채워진다.
- 움직임과 조작: `LTT.sweep` 로그 슬라이더(N 1–100, `kind: "log"`). 목표 문구 "요청 p99를 150 ms 아래로 지키는 최대 N을 찾는다".
- 비트: ① N=1은 두 패널이 동일. ② 슬라이더를 올리면 아래만 움직임(위는 고정, 대비가 강조점). ③–④ 100 ms 오른쪽 면적이 9.6 → 63%, 요청 p50 표식이 위 패널의 p99 선 옆까지 온다. ⑤ 요청 p99 표식 약 397 ms.
- 실패 위험: 최댓값 분포(F^N)가 "평균이 아니라 최댓값"이라는 직관 없이 추상적으로 보일 수 있다. 비트 ②에 작은 레인 3줄 삽화를 달아 보완해야 한다.

### c3 · 요청 100칸 와플 (뼈대: 모집단 비율, "요청 100개 중 몇 개가 느린가")
- 배치: 전면. 왼쪽 큰 10×10 와플(칸 하나 = 요청 하나, 느린 칸은 `--ltt-bad`), 오른쪽에 N 손잡이와 세 줄 표(N, 느린 요청 %, 요청 p50/p99). 칸 하나를 누르면 그 요청의 호출 N개 점(일부만)이 펼쳐진다.
- 움직임과 조작: `LTT.sweep` `steps` 정지점 1, 10, 50, 100만(비트와 일치). 전환 때 칸이 좌상단부터 순서대로 빨갛게 바뀐다. 칸 배정은 고정 순열 u_i로 해 N이 커질 때 이미 빨간 칸은 그대로 유지(단조).
- 비트: ① 빨간 칸 1개. ② 칸 하나를 펼쳐 "가장 늦은 호출이 요청을 붙잡음" 설명. ③ 10칸 안팎. ④ 39.5 → 63.4칸, "꼬리가 다수". ⑤ 하단 주석으로 요구 백엔드 p99.99.
- 실패 위험: 와플 칸 수 = 정수 반올림이라 39.5가 40, 9.6이 10으로 보여 숫자와 어긋난다. 수치 라벨은 항상 모델 값(소수 한 자리)을 쓰고 칸은 근사임을 밝힌다.

### c4 · 한 요청의 부채꼴 + 자동 재생 비트 (뼈대: 호출 트리, 방사 구조)
- 배치: 좌우 분할. 왼쪽 정사각 칸에 요청(중앙 위)이 N개 백엔드(아래 호 위의 점)로 갈라지는 부채꼴과 시계. 오른쪽에 P(N) 큰 수치와 요청 p50/p99 두 줄.
- 움직임과 조작: 자동 재생 비트가 주(主). 5개 비트가 N=1 → fan-out → 10 → 50 → 100 순서로 약 18초 주기로 진행하고 끝에서 손잡이(`LTT.sweep` `steps`)가 열려 자유 조작. 호출 점마다 도착 시각이 다르며 마지막 점이 켜질 때 "완료" 도장이 찍힌다.
- 비트: ① 점 하나. ② 선이 N개로 펴지고 도착 순서대로 점이 켜짐, 마지막 점에서 완료. ③–④ N 증가에 따라 느린 점(빨강)이 한 개라도 있는 라운드 수가 늘어남을 우측 수치가 따라감. ⑤ 정지 후 손잡이.
- 실패 위험: 비트 재생 중 손잡이와 재생이 서로 값을 덮어쓰기 쉽다(조작 시 재생 정지가 필요). N=100 점이 호 위에 겹친다.

### c5 · 요구 수준 사다리 (뼈대: 역방향 읽기, 요청 목표 → 백엔드 퍼센타일)
- 배치: 위아래. 위는 x = N(로그) y = 필요한 백엔드 퍼센타일(99, 99.9, 99.99 눈금)의 계단식 곡선 두 개(요청 p50, 요청 p99). 아래는 한 줄 읽기 띠 "N=100 → 요청 p99를 지키려면 백엔드 p99.99(=100번 호출당 한 번 미만의 꼬리)".
- 움직임과 조작: `LTT.sweep` 로그 N 손잡이와 대상 선택(p50/p99 토글). 곡선 위 점이 움직이며 y 읽기 표식이 따라온다.
- 비트: ①–② 문서 상단 짧은 설명(요청 지연 = 최댓값). ③–④ 곡선이 올라가며 p50도 99 위로 올라감. ⑤ 결론이 곡선의 끝점으로 곧바로 보임.
- 실패 위험: 비트 ③·④의 "느린 요청 비율 치솟는 곡선"이 강조점이어야 하는데 이 구성안은 퍼센타일이 주인공이라 강조점이 한 단계 뒤로 간다. 요청 비율 곡선을 작게 곁들여야 한다.

## 추천: c1
이유: 스토리보드의 강조점(비율 곡선이 N과 함께 치솟음)과 가장 먼저 필요한 직관(요청 = 가장 느린 호출)을 한 화면에서 동시에 보인다. 레인과 곡선이 같은 N 손잡이로 움직여 sweep 역할에 맞고, 백엔드 분포가 고정이라는 대비는 100 ms 꼬리선과 막대 길이 분포가 매번 같은 모양이라는 점으로 암시된다. c2가 대비는 더 선명하지만 분포 변환이 처음 보는 독자에게 추상적이다. 레인 가독성 위험은 N=100을 점 줄 표현으로 낮추는 것으로 막는다.

## 검사 지점
- k1 · N=1: 레인 한 줄, 완료선이 그 막대 끝과 같다. 느린 요청 1.0%, 요청 p99 = 백엔드 p99 = 100 ms(같다고 읽힘).
- k2 · N=10: 느린 요청 9.6%(0.0956 ± 0.001), 요청 p50 ≈ 44 ms, p99 ≈ 213 ms. 레인의 막대 길이 분포와 100 ms 선 위치는 N=1과 같다.
- k3 · N=50, N=100: 39.5% → 63.4%, 값은 단조 증가이고 100%를 넘지 않는다. 곡선 점이 수치 표시와 같은 위치에 있다.
- k4 · 임의의 재생 시점: 요청 완료선 위치 = 그 순간 가장 긴 막대의 끝. 호출 평균 지연 표시는 N과 무관하게 그대로다.
- k5 · N=100: 요청 p50 ≈ 114 ms로 100 ms 선 오른쪽(백엔드 p99.3 근처), 요청 p99 ≈ 397 ms, 주석에 "백엔드 p99.99 필요".
- k6 · N을 바꾸는 전 구간: 백엔드 p50 = 10 ms / p99 = 100 ms 표식이 움직이지 않는다(백엔드는 바뀌지 않음). 곡선 한 점은 항상 현재 N을 가리킨다.
- k7 · 칸 안에 전부 보임: 큰 폭과 400px 폭 모두에서 레인·곡선·수치가 칸 안에 들어오고 viewBox 비율이 찌그러지지 않는다. SVG 글자는 14px 이상, 라벨이 막대와 겹치지 않는다.
- k8 · reduced-motion과 재생 정지 상태에서도 완료선, 꼬리 막대(`--ltt-bad`), 비율 수치가 정지 화면 한 장으로 읽힌다. 색은 토큰만 쓴다(hex 없음).
