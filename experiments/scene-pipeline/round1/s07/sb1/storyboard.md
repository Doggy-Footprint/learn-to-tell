# 스토리보드 · fan-out과 p99 꼬리 지연 (sweep)

## 독자가 말할 수 있어야 하는 한 문장
한 요청이 부르는 백엔드 수 N이 커질수록 "그중 하나라도 느릴" 확률이 1 − 0.99ᴺ으로 커져서, 백엔드 하나에서는 드물던 p99 지연이 사용자 요청에서는 흔한 일이 된다.

## 인과 사슬
1. 백엔드 하나는 대부분 빠르고, 호출 100번 중 1번꼴(1%)로 느리다(p99 꼬리).
2. 요청 하나가 N개 백엔드를 병렬로 부르고, 응답이 모두 와야 끝난다.
3. 그래서 요청 지연 = N개 호출 중 **가장 느린 것**의 지연.
4. N개 중 하나라도 꼬리에 걸릴 확률 = 1 − 0.99ᴺ → N에 따라 빠르게 커진다.
5. 결과: 요청의 p50·p99가 백엔드 꼬리 쪽으로 밀려 올라간다. 백엔드 자체는 하나도 안 바뀌었다.

## 화면에 꼭 보여야 할 것
- 대상: 요청 1개, 거기서 갈라지는 N개 백엔드 호출, 각 호출의 지연, 요청 완료 시점(가장 늦은 호출).
- 관계: 요청 완료 = max(호출 지연). 느린 호출 하나가 요청 전체를 붙잡는다.
- sweep 변수: N = 1 → 10 → 50 → 100. 함께 움직이는 값: "꼬리에 걸린 요청 비율"과 요청 p50/p99.
- **강조점 하나: 요청 중 느린 비율(1 − 0.99ᴺ)이 N과 함께 치솟는 곡선.** 백엔드 분포는 고정이라는 점을 대비로 둔다.

## 사실 점검표
- 가정: 백엔드 호출 지연은 서로 독립, 같은 분포. 예시 분포: p50 = 10 ms, p99 = 100 ms (단위 ms, 꼬리는 100 ms 이상).
- 방향: N↑ → 느린 요청 비율↑, 요청 p50·p99↑. 반대 방향은 없다(단조 증가).
- 범위: 비율은 0~1. N=1일 때 정확히 1%. N→∞이면 1에 다가가되 넘지 않는다.
- 손 계산 (P = 1 − 0.99ᴺ):
  - N=1: 1 − 0.99 = 1%
  - N=10: 0.99¹⁰ ≈ 0.904 → 약 9.6%
  - N=50: 0.99⁵⁰ = e^(50·ln0.99) ≈ e^(−0.503) ≈ 0.605 → 약 39.5%
  - N=100: 0.99¹⁰⁰ ≈ 0.366 → 약 63.4%
- 요청 백분위 ↔ 백엔드 백분위: 요청 지연 ≤ t ⇔ 모든 호출 ≤ t, 즉 F(t)ᴺ.
  - N=100에서 요청 p50: F = 0.5^(1/100) ≈ 0.9931 → 백엔드 p99.3 근처 (≈100 ms 이상). 요청의 "중간값"이 백엔드의 꼬리다.
  - N=100에서 요청 p99: F = 0.99^(1/100) ≈ 0.9999 → 백엔드 p99.99가 필요하다.
- 평균이 아니라 최댓값이 결정한다: 호출 평균 지연은 N과 무관하게 그대로다.
- 병렬 호출 기준이다. 직렬 호출(합)과 섞지 않는다.

## 흔한 오해와 깨는 순간
- 오해: "백엔드 p99가 100 ms면 1% 요청만 느리다. 백엔드를 늘려도 평균이 같으니 사용자 지연은 비슷하다."
- 깨는 순간: 백엔드 분포 그림은 한 픽셀도 안 바뀐 채 N만 100으로 올리면, 요청 3개 중 2개 가까이(63%)가 100 ms 이상에 걸린다. 1%짜리 꼬리가 사용자에게는 "보통"이 된다.

## 비트
1. N=1: 요청 = 호출 하나. 느린 요청은 1%. → "백엔드 p99와 요청 p99가 같다."
2. 요청 하나가 N개를 병렬로 부르고 가장 늦은 것을 기다린다. → "요청 지연은 평균이 아니라 최댓값이다."
3. N=10: 느린 요청 약 9.6%. → "1%가 10배 가까이 됐는데 백엔드는 그대로다."
4. N=50 → 100: 39.5% → 63.4%. → "꼬리가 다수가 됐다. 요청 p50이 백엔드 p99 근처다."
5. 결론: N을 정하는 것이 곧 백엔드에 요구하는 꼬리 수준을 정하는 것. → "N=100에서 요청 p99를 지키려면 백엔드 p99.99가 필요하다."
