# direction

## 초안 a
- 표현: 5노드를 오각형으로 놓은 직접 그린 SVG. 노드 카드에 역할·term·로그 칸(커밋 실선/미커밋 점선), 아래에 득표·저장 칸 5개와 과반선, 점이 메시지로 이동. 9단계 자동 반복.
- 맞는 점: 선출 → 리더 → 미커밋 append → 복제 → 3번째 ack에 커밋 순서, 과반선 하나로 선출·커밋을 같이 보임, 득표 3/3 계산.
- 어긋난 점: 3단계에서 C·D·E의 term이 B의 요청 전에 2로 오른다(요청이 먼저 가야 함). 당선 뒤 heartbeat 단계가 없다. 마지막에 E까지 한꺼번에 커밋(팔로워 갱신은 리더보다 늦고 E는 더 늦어야 함). 조작이 없다.
- 결함 코드: 그림이 화면 8~10%(figure 폭만 쓰고 글이 많음). overview-order 지적은 단일 장면이라 무시.

## 초안 b
- 표현: LTT.diagram + player로 노드 하이라이트와 점 이동. 7단계 캡션.
- 맞는 점: 단계 순서, 사실(과반 3).
- 어긋난 점: 로그 칸·term·득표 표시가 없어 "미커밋→커밋"과 문턱이 화면에 안 보인다. 하이라이트만 바뀌어 메커니즘이 글에 의존한다.
- 결함 코드: shrunk 78~84%, glossary term·heartbeat 미사용.

## 가져올 것
- a의 SVG 구도, drawNode 로그 칸, 득표/저장 칸 + 과반선, send 점 애니메이션, 단계 자동 반복.
- b의 번호 캡션 문장 일부.

## 최종 방향
화이트보드 위 5노드 클러스터 한 장이 주인공(layout full). 각 노드는 역할·term·로그 칸을 갖고, 하단 5칸 막대 + 과반선(3)이 선출 때는 득표, 복제 때는 저장 수를 센다. 비트: ①평시 heartbeat → ②A 정지, B timeout → ③B term 2·후보·자기 1표 → ④RequestVote 점이 나감(수신 노드가 그때 term 2) → ⑤C·D 표 회신, 3표로 과반선 돌파 → ⑥B 리더, heartbeat → ⑦x가 B에 미커밋 칸으로 생김 → ⑧AppendEntries 발송, C·D 저장(E는 지연) → ⑨ack 회신으로 저장 3, B만 x를 커밋 → ⑩다음 AppendEntries로 C·D, 뒤늦게 E가 커밋. 조작: 이전/다음/자동 재생 버튼과 단계 점 클릭. 글은 단계 자막, 부제, takeaway(노드 수와 허용 장애, 홀수 권장), recall.
