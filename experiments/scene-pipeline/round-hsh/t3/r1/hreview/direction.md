# 방향 정하기: Raft 리더 선출과 로그 복제 (overview 한 장)

## 1. 초안 점검

- **a (5각형 SVG 직접 그림)**: 노드 다섯을 오각형으로 놓고 점 메시지를 rAF로 움직인다. 과반선이 있는 5칸 막대가 득표·저장 수를 보여 주고, 장애 노드는 점선·흐림으로 그린다. 비트 9개가 생성 순서(term → RequestVote → 당선 → append → 복제 → 커밋 → 전달)를 따른다. 결함: 오버뷰 한 장에 그림이 `stage`로 전부 들어가고 audit은 그림이 화면의 8–15%뿐이라고 본다. 글(캡션·takeaway·basis)을 계속 얹어 그림이 줄어든다.
- **b (LTT.diagram + steps)**: 3열 격자에 노드 5개와 엣지 10개를 깔고 `player`로 단계를 넘긴다. 역할·로그는 그림 아래 표로 준다. 단계 순서는 맞지만, 로그 칸이 글자 표라 "복제 진행"과 "커밋 전이"가 그림에서 안 보인다. 용어 `term`·`heartbeat`를 본문에서 쓰지 않아 audit이 미사용 용어 2건을 권고했다.
- **c (diagram + 우측 패널, 상태 누적 계산)**: 격자 그림이 주인공이고, 오른쪽 패널에 노드별 `term·역할·로그 칸`(진한 칸=커밋, 점선 칸=미커밋)과 득표·저장 확인 막대(세 번째 칸 뒤가 과반선)를 둔다. 상태는 `OPS`를 0번부터 누적 적용해 계산하므로 앞뒤로 넘겨도 같은 칸이 나온다. 11단계가 스토리보드 생성 순서와 일치한다. audit 결과는 1440에서 고침·권고 0, 1280에서 권고 1건(shrunk 86%)이다. 결함: 용어 `term`에 풀이가 없고, "복제 전에 죽으면 덮어쓰일 수 있다"는 깨는 순간이 빠져 있다.
- **d (figure + 표 + 단계 `set`)**: 표 중심이고 그림이 작다. audit에서 small-visual 15–19%, 용어 2건 미사용, 권고 여러 건. 그림이 주인공 역할을 못 한다.

## 2. 가져올 것

- **c를 뼈대로 쓴다.** 그림이 주인공이고, 상태가 단계마다 같은 규칙으로 계산되며, audit이 가장 깨끗하다. 스토리보드의 "화면에 꼭 보일 것" 네 가지(노드별 term·역할·로그, 득표 대 과반 기준선, 미커밋/커밋 구분과 복제 진행, 과반 강조)를 모두 담는다.
- **a에서**: 장애 노드를 흐리게 보는 생각은 c에 그대로 두기 어렵다(진단 노드 옵션이 없음). 대신 c의 패널에서 S1 줄의 "장애" 태그를 그대로 쓴다. 과반선을 막대 세 번째 칸 뒤에 두는 방식은 c 것이다.
- **b에서**: 없음(표 중심 구성은 가져오지 않는다).
- **d에서**: 없음.

## 3. 최종 방향

**그림의 뼈대**: 3×3 격자 `LTT.diagram`에 서버 5대(S1–S5)를 놓는다. S1은 위 가운데(기존 리더), S2는 왼쪽 가운데, S3는 오른쪽 가운데, S4·S5는 아래 두 칸이다. 그림 오른쪽에 패널 하나를 두고, 패널 행마다 `노드 · term · 역할 · 로그 칸`을 준다. 패널 맨 아래에는 득표 막대와 저장 확인 막대(5칸, 세 번째 칸 뒤가 과반선)를 둔다.

**비트별 움직임(11단계, 생성 순서)**:
1. 평시: S1이 heartbeat를 S2–S5로 보낸다(회색). 모두 term 3.
2. S1이 멈춘다(장애 태그). S2의 election timeout이 먼저 끝난다. 강조는 S2.
3. S2가 term 4로 올라 후보가 되고 자기 한 표를 찍는다. 득표 1/3.
4. S2가 RequestVote를 S3·S4·S5로 보낸다(파란 점). S3–S5의 term이 4로 바뀐다.
5. S3·S4가 표를 준다(초록 점). 득표 3/3, 과반선에 닿아 S2가 리더가 된다.
6. S2가 빈 AppendEntries를 보내 권위를 알린다.
7. 쓰기 x가 S2 로그에 미커밋(점선 칸)으로 붙는다. 저장 확인 1/3. 글: 지금 리더가 죽으면 덮어써질 수 있다.
8. S2가 x를 S3·S4에 복제한다. 두 노드 칸이 점선으로 생긴다.
9. S3·S4가 저장 ack를 보낸다. 저장 확인 3/3, S2가 x를 커밋해 진한 칸이 된다.
10. 다음 AppendEntries로 커밋 위치가 S3·S4·S5에 전해진다. S3·S4가 커밋 칸이 되고, 늦은 S5도 x를 받아 커밋 칸이 된다.

(사용: 단계 재생 `player`, 이전·다음·반복 재생. 자동 재생 후 반복.)

**조작**: 손잡이는 없다. 단계 재생만 쓴다(조작이 배움이 아니므로).

**화면에 얹을 글**: 제목 "리더는 과반 표로 뽑히고, 과반이 저장한 항목만 커밋된다". 부제에 {{과반}}과 {{term}}을 쓴다. 캡션은 단계마다 짧은 한 문장. 그림 설명은 "진한 칸은 커밋, 점선 칸은 미커밋. 막대 세 번째 칸 뒤가 과반선이다." takeaway는 "선출과 커밋은 같은 과반을 쓰므로 5노드는 2대가 죽어도 합의가 유지된다."
