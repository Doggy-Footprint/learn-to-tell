# direction

## 초안 a
- 표현: 서버 5대를 오각형으로 놓고 가운데 패널에 "n/5 표 → n/5 저장" 점 5개를 둔다. 서버 상자 안에 role, term, 로그 칸(index 4~7). 패킷(생존 신호, 투표 요청, 표 줌, 복제, 저장 확인, 커밋 전달)이 상자 사이를 이동한다. 조작은 "다시 보기"뿐.
- 점검표·순서: term+1과 자기 투표 → 요청 → 표 → 3/5에서 리더, index 7이 리더에 미커밋(점선)으로 먼저 생기고 복제 뒤 3/5 확인에서 커밋, 팔로워 커밋은 "커밋 7 전달" 뒤라 한 박자 늦다. 모두 맞다. S4가 죽은 경우는 없다. 오해("모든 서버가 받아야 커밋")를 깨는 장면이 약하다.
- 결함 후보: overview 순서 lint(무시 대상), 자막이 길어 78%로 축소, 3대 장애로 멈추는 반례가 없다. 재생 중 setTimeout 취소는 run 토큰으로 처리돼 괜찮다.

## 최종 방향
그림 뼈대: 서버 5대 오각형 + 가운데 과반수 패널(선출 표와 저장 수가 같은 점 5개로 번갈아 쓰인다 = 두 곳의 같은 역할). 움직임 순서: 리더 S1 생존 신호 → S1 멈춤 → S3 타이머 종료, term 4와 자기 표 → 투표 요청 → 표가 돌아와 3/5에서 리더 → 생존 신호 → index 7이 리더 로그에 미커밋 → 복제 → 저장 확인 3/5에서 커밋 → 다음 메시지로 팔로워 커밋. 조작: "다시 보기"와 "서버 3대 멈춤" 버튼. 후자는 S1·S4·S5가 멈춘 채 같은 선출을 돌려 2/5에서 멈추는 것을 보인다. 글: 한 줄 자막, 짧은 sub, takeaway, recall.
