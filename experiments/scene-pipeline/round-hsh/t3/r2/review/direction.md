# direction

## 초안별
**a**: 서버 5대를 오각형으로 놓고 가운데 패널에 표/저장 점 5개와 "n/5"를 둔다. 서버 상자 안에 역할·term·로그 칸(index 4~7). 메시지 라벨이 상자 가장자리 사이를 움직이고, 자막이 10단계를 설명한다. 다시 보기 버튼. 생성 순서(term+1·자기 표 → RequestVote → 과반 → 리더 → heartbeat → 리더 로그 미커밋 → 복제 → 과반 ack → 리더 커밋 → commitIndex 전달 후 팔로워 커밋)를 정확히 따른다. 어긋남: RequestVote를 받은 S5의 term이 뒤늦게(⑥) 오르고, S2·S4만 도착 때 오른다. 화면 결함 코드는 없음(audit는 overview-order만).
**b**: LTT.diagram 별 모양 + 아래 표 형식 로그 행 + player. 순서는 맞지만 그림(노드)이 작고 로그가 표로 밀려 그림이 주인공이 아니다. 표는 S2가 후보인데 S1 장애 표시가 점선뿐이다. 표 행 텍스트가 무겁다.
**c**: diagram 오각형 + 모든 쌍 점선 + player. 로그·term 상태가 노드 부제 정도라 커밋 전후가 화면에 안 보인다. 그림이 작다(small-visual).
**d**: SVG로 직접 그림, 반복 재생, 가운데 과반수 3/5와 원 5개, 커밋 실선/미커밋 점선. 순서 정확. 어긋남: 과반수를 "3/3 필요"로 표기, S4 죽음을 가정해 S1이 후보인 설정이 단순하다. shrunk 78% 권고(그림 높이+글이 큼).

## 가져올 것
a의 전체 골격(오각형 상자, 가운데 과반수 패널, 패킷 라벨, 로그 칸, 10단계 자막, 다시 보기)과 d의 미커밋 점선/커밋 실선 구분. a의 term 갱신 시점을 RequestVote 도착 때로 고친다.

## 최종 방향
오각형 서버 5대가 화면의 주인공. 가운데 패널이 "n/5" 과반수 계량기로 선출 때는 표, 복제 때는 저장을 센다. 비트: S1 heartbeat → S1 멈춤 → S3 timeout, term 4, 자기 표 → RequestVote(도착한 서버 term 4) → 표 두 장으로 3/5 → S3 리더 → heartbeat → index 7이 리더 로그에 점선 미커밋 → 복제 → ack 2장으로 3/5 → 리더 칸만 실선 커밋 → commitIndex를 실은 메시지가 오면 팔로워 칸이 실선. 조작은 "다시 보기" 버튼. 글은 그림 아래 한 줄 자막, 패널 안 짧은 라벨, 정리 문장.
