## 초안별

**a (N0~N4, 오각형, 9단계 send 재생)**
- 표현하려 한 것: 5노드 오각형 위에 heartbeat·투표·AppendEntries 패킷을 단계마다 흘린다.
- 점검: 생성 순서(append → 복제 → 커밋 → ack)와 과반수 계산은 맞다. 어긋남: 노드 라벨 "term 2 · 로그 1–2"가 정적이라 term과 로그가 단계마다 바뀌지 않는다. ⑨ 자막은 N3가 죽는다고 하지만 N0는 끝까지 "리더"로 남고, 새 리더 전환이 그림에 없다.
- 결함: a-audit small-visual(그림이 화면의 21%). 760×420 그림에 노드 150×56이라 글이 작다.

**b (A~E, 3×3 격자 + 노드 카드 + 13비트)**
- 표현하려 한 것: 노드마다 카드(term, index:term 칸, 커밋 경계 칸)를 두고, 비트마다 render로 값을 바꾼다.
- 점검: 생성 순서가 가장 충실하다(타이머 → 후보 term+1 → 투표 → 리더 → append → 복제 → 과반수 커밋 → ack → 팔로워 커밋 → 리더 사망 → 재선출 → 단절 노드 따라잡기). 어긋남: E는 ⑥에서 복제 대상인데 로그는 ⑩에서 처음 갱신된다. 쌍마다 엣지 10개가 가운데에서 엉킨다.
- 결함: b-audit shrunk 78%. 격자 260×170 3행 + 카드 + 컨트롤이 한 칼럼이라 축소된다.

**c (S1~S5, overview steps 7단계)**
- 표현하려 한 것: 중앙 S2가 후보에서 리더가 되는 구도, S1은 heartbeat가 끊긴 옛 리더.
- 점검: 자막의 투표·복제·커밋 순서는 맞다. 어긋남: 노드 라벨 "term 3 · 1:t1 2:t2 3:t3 · commit 2"가 처음부터 고정이라 3번째 항목을 가진 채로 시작하고, 커밋 경계가 단계에 따라 바뀌지 않는다.
- 결함: c-audit shrunk 81%(1440), 78%(1280).

**d (3×3 그림 + 옆 상태표 7행, 8단계)**
- 표현하려 한 것: 옆 표가 단계마다 term·역할·표·로그·저장 수·commitIndex를 갱신한다. 클라이언트 C가 쓰기를 보낸다.
- 점검: 값의 순서는 대체로 맞다(후보 term 2, 리더, append 미커밋, 3/5 커밋, ack, 팔로워 커밋). 어긋남: 리더 사망과 재선출을 다루지 않고, 글 표가 그림보다 커서 글 중심이다.
- 결함: d-audit shrunk 84%(1280). 옆 칼럼 280px이 그림 폭을 줄인다.

## 최종 방향
그림 뼈대: 5노드 오각형(픽셀 좌표, 760×340, 노드 160×52)이 주인공이다. 쌍마다 옅은 점선 엣지를 깔고, 그림 아래에 노드 카드 다섯 장(A~E: 역할 태그, term, index:term 칸, commit 칸)을 한 줄로 둔다. overview이고 `layout: "full"`로 그림이 칸을 쓴다.

비트(생성 순서, 단계마다 hold 2600ms):
1. 정상: A 리더의 heartbeat가 B~E로 간다. 카드는 모두 term 2, 로그 1–2, commit 2.
2. A가 끊긴다(A "단절"). B의 타이머가 먼저 끝난다(B 강조).
3. B가 후보가 되어 term 3, 자기 표, 투표 요청 B→C·D·E.
4. C·D·E가 term 3에 한 표씩 B에게 준다. 자기 표 포함 3표 = 과반수.
5. B가 리더. A는 term 2를 믿는다.
6. B가 index 3(term 3)을 자기 로그에 append한다. 아직 미커밋.
7. AppendEntries B→C·D·E.
8. C가 저장 응답(2개, 미커밋).
9. D가 저장 응답 → 5개 중 3개, index 3 커밋, B의 commit 3이 밝아진다. 강조점.
10. 커밋 뒤에야 B가 클라이언트에 ack.
11. 다음 heartbeat로 C·D가 commit 3, E가 밀린 index 3을 받는다.
12. B가 죽는다(B "죽음"). C가 term 4 후보, 표 요청 → D·E 표 → C 리더. index 3은 C에게 남는다.
13. 단절이 풀린 A가 term 4 팔로워로 내려가 index 3을 받아 따라잡는다.

조작: 없음. 자동 재생과 이전·다음 단계 재생(player). 반복은 leave에서 멈춘다.
