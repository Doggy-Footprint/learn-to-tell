# direction

## 초안별
**a**: 오각형 diagram에 heartbeat·투표·복제 패킷을 9단계로 보낸다. 조작은 player뿐이고 노드 상자에는 "term 2 · 로그 1–2" 글만 있어 단계가 바뀌어도 로그가 변하지 않는다(그림은 고정, 자막만 바뀜). 순서는 맞다(term↑ → 투표 → append → 복제 → 커밋 → ack). 어긋남: 단계 ⑤⑥의 상태가 노드 글에 반영되지 않아 "커밋 경계"가 안 보인다. 결함 코드: 그림이 작아 small-visual 권고.
**b**: 오각형 diagram + 노드별 카드(역할 태그, term, index:term 칸, commit 칸 색). `BEATS`의 `set`을 누적해 단계별 상태를 만들고 `enter`에서 다시 그리므로 되돌려도 같은 화면이다. 12비트가 생성 순서와 사실 점검표(2개 저장은 미커밋, 3개째 커밋, 팔로워 commit은 한 박자 늦음, ack는 커밋 뒤, 단절된 옛 리더 복귀)를 모두 지킨다. 어긋남: 과반수 "3개" 순간을 한눈에 세는 장치가 없다. 결함: 그림+카드가 커서 78%로 줄어듦.
**c**: 노드 5개에 글만 얹은 고정 figure + 패킷 7단계. 노드 글(S2 로그 3:t3 commit 2)이 처음부터 완성 상태라 append·커밋 순서와 어긋난다. 상태가 변하지 않는다.
**d**: diagram + 오른쪽 상태 패널(term, 역할, 투표, 저장 수 n/5, commitIndex). 순서와 수치는 맞고 "저장 1/5 → 3/5 → 커밋"이 강조점을 준다. 어긋남: 팔로워 로그를 문장으로만 적고 노드별 로그 칸이 없다. 패널이 그림 옆에 붙어 좁다.

## 가져올 것
b의 BEATS/`set` 누적 구조, 카드(index:term 칸, 커밋 칸 색), sendAll 헬퍼, 12비트 서사. d의 "저장 n/5 → 과반수" 아이디어를 점 5개짜리 계량 띠로 바꿔 카드 위에 둔다. a의 클라이언트 ack 개념은 diagram에 클라이언트 노드를 두어 ack 패킷으로 보인다.

## 최종 방향
오각형 노드 5개(A–E) diagram이 주인공이고, 아래에 노드별 로그 카드가 한 줄로 있다. 비트 순서: heartbeat → A 단절·B timeout → B 후보, term 3 먼저 올라감 → C·D·E 투표(term 3) → B 리더 → 쓰기가 B 로그에 점선(미커밋) 칸으로 생김 → AppendEntries → C 저장(2/5, 미커밋) → D 저장(3/5, 계량 띠가 채워지며 칸이 실선·초록으로 바뀌고 B commit=3) → 클라이언트 ack 패킷 → 다음 heartbeat로 팔로워 commit 따라감 → B 사망, C 후보 term 4 → C 리더, 커밋 항목 보존 → A 복귀. 조작은 player의 이전/다음/반복 재생이고 enter가 상태를 통째로 다시 그려 되돌려도 같다. 글은 단계 자막과 한 줄 sub, 카드 칸 표기(index:term)만 얹는다.
