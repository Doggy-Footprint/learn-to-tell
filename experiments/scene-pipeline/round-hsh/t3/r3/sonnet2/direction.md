# direction

## 초안 a
- 표현: 오각형 diagram(N0~N4)에 패킷을 보내고 highlight만 바꾸는 9단계 재생. 로그 칸·term은 그림에 없고 자막에만 있다. 조작은 player의 이전·다음.
- 점검: 순서(타이머→term 상승→투표→append→복제→커밋→ack→재선출)는 맞다. 그러나 N3가 term 2→3 때 N0를 여전히 살아 있는 투표자로 두고, 로그·commitIndex가 화면에 없어 "3번째 저장 순간 커밋"이 안 보인다. sub의 `{{과반수}}`는 문장이 비어 읽힌다.
- 결함 코드: 장면 한 개인데 overview-order lint(덱 순서라 무시), small-visual(그림 21%) — 그림이 760x420 고정이고 글 비중이 크다.

## 초안 b
- 표현: diagram + 아래 노드 카드 5장(역할 태그, term, index:term 칸, commit). 13개 비트가 상태 객체(`BEATS`→`states`)로 한 번에 정의되고, enter에서 카드를 다시 그린다.
- 점검: 사실은 대체로 맞다(B가 2/5에서 미커밋, 3/5에서 커밋, ack는 커밋 뒤, 팔로워 commit은 다음 heartbeat). 어긋난 점: 단절된 A를 마지막에 되살려 흐름이 길고, 카드 5장+그림이 세로로 쌓여 78%로 줄었다.
- 결함 코드: `shrunk` 권고(세로 적층), 지도 같은 3x3 격자에 노드 배치가 성겨 그림이 작다.

## 가져올 것
- b의 상태 객체 구조(`BEATS`의 `set`을 누적해 `states` 만들기)와 칸 색 규칙(커밋=밝게, 미커밋=점선).
- a의 픽셀 좌표 오각형, 단계마다 `send`로 패킷을 보내는 방식.

## 최종 방향
- 뼈대: 왼쪽에 큰 오각형 diagram(노드 N0~N4, 모든 쌍 점선), 오른쪽에 같은 5노드의 로그 칸 보드(역할, term, index 1~3 칸, 빈 칸은 점선). 보드 위에 "index 3 저장 n/5" 5알 카운터. 가로 배치라 세로로 쌓이지 않는다.
- 비트: ① 정상 heartbeat(N0 리더, 전원 로그 1–2) → ② N0가 끊기고 N3 타이머가 먼저 만료 → ③ N3 후보, term 3(투표 요청 패킷) → ④ N1·N2·N4 응답, 자기 표 포함 3표 이상이라 N3 리더 → ⑤ 쓰기가 N3 로그 칸 3에 점선으로 생김(미커밋, 1/5, "여기서 죽으면 사라진다") → ⑥ AppendEntries 패킷 → ⑦ N1 저장 2/5 미커밋 → ⑧ N2 저장 3/5, 칸이 밝아지며 커밋, ack → ⑨ 다음 heartbeat로 팔로워 commit 3, N4에도 칸 3 → ⑩ N3도 죽어도 N1이 term 4로 당선, 커밋 칸은 남는다.
- 조작: player의 이전·다음·반복 재생. 글: 단계 자막, 제목, 한 줄 sub, 카운터 라벨. N0는 죽은 채 유지해 "5대 중 2대 장애까지 견딤"을 보인다.
