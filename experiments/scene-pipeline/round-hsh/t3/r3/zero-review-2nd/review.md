# 검수: Raft 합의 장면 (overview)

스크린샷 주의: `shots/` 3장(t1s·t4s·t8s)은 바이트 크기가 같고 모두 첫 장면 summary(01/03)다. overview 단계는 캡처되지 않아 아래 overview 판정은 코드(`scene.html`)를 근거로 했다.

## 사실 점검표

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| 과반수 floor(N/2)+1, N=5→3, 허용 장애 2 | 통과 | scene.html:18-20 (MAJ, LTT.expect), summary 카드 01 |
| 손 계산: 리더+팔로워 2=3 커밋, 1=2 미커밋 | 통과 | scene.html:39-43 (S[4] "저장 2/5 미커밋", S[5] "저장 3/5 ≥ 3") |
| 투표 요청 term+1, term당 한 표, 높은 term에 리더 강등 | 통과 | scene.html:29-35 (후보 T1 → 리더). 강등 장면은 없고 모순도 없음 |
| election timeout 무작위, heartbeat 주기 | 통과 | 수치 미표시. scene.html:73 caption ①과 모순 없음 |
| 후보 로그가 덜 최신이면 표를 못 받음 | 실패 | scene.html:50 N2 간선 "표 요청 T2"에 거절 표시가 없고 N3만 "거절". N2도 ▣1을 가져 거절해야 함 |
| 리더 로그 덮어쓰기 가능, 커밋 항목은 안 지워짐 | 통과 | scene.html:77 caption ⑧, ctr "커밋 ▣1 보존" |

## 생성 순서

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| 리더가 자기 로그에 먼저 쓰고 그다음 복제 | 통과 | S[3] L·▢1 → S[4] AppendEntries |
| term이 선출 결과보다 먼저 바뀜 | 통과 | S[1] C·T1 → S[2] L |
| 커밋은 복제 응답 과반수 뒤 | 통과 | S[4] "저장 2/5" → S[5] "저장 3/5 ≥ 3, 커밋" |

| ack는 커밋 뒤 | 통과 | S[3] client "write" → S[5] client "ack" 와 ▣ 동시 |
