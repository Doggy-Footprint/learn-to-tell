# 스토리보드: TCP 혼잡 제어 (predict)

## 독자가 말할 수 있어야 하는 한 문장
"손실이 나면 cwnd는 절반으로만 깎이고(타임아웃이면 1로) 그 뒤 RTT마다 1 MSS씩 느리게 오르기 때문에, 처리량은 톱니의 평균(최고점의 약 75%)에 머문다."

## 인과 사슬
1. 연결 시작: cwnd = 초기 윈도(예: 10 MSS), ssthresh는 사실상 무한대.
2. slow start: ACK 하나마다 cwnd가 1 MSS 늘어 RTT마다 약 2배(지수 증가).
3. 송신량이 병목 링크의 BDP + 큐 용량을 넘으면 큐가 차고 패킷이 버려진다.
4. 수신자가 중복 ACK를 보낸다. 3번째 중복 ACK에서 송신자가 손실을 감지한다.
5. 반응: ssthresh = cwnd/2, cwnd = ssthresh (Reno 기준, 빠른 회복). 곱셈 감소.
6. cwnd ≥ ssthresh이므로 congestion avoidance: RTT당 +1 MSS (덧셈 증가).
7. 다시 한계에 닿으면 4~6 반복 → AIMD 톱니.
8. 중복 ACK가 모자라 RTO가 터지면: ssthresh = cwnd/2, cwnd = 1 MSS, 다시 slow start (톱니가 바닥까지 무너짐).

## 화면에 꼭 보일 것
- cwnd(MSS 단위) 시계열: 가로 RTT 또는 시간, 세로 cwnd.
- ssthresh 수준, 손실 시점, 병목 용량(BDP+큐) 한계선.
- 구간 구분: slow start / congestion avoidance / 손실 반응.
- 강조점 하나: 손실 직후 cwnd가 어디로 떨어지는가(절반 vs 1).

## 생성 순서 (틀리기 쉬움)
- 손실이 먼저, ssthresh 갱신이 그 다음, cwnd 하강이 마지막이다. ssthresh는 "손실 시점의 cwnd"의 절반이므로 손실 전 cwnd 값이 있어야 정해진다.
- slow start 곡선은 ssthresh 갱신 이후가 아니라 그 이전에 있다. 첫 구간의 ssthresh는 아직 의미 없다.
- 톱니의 오른쪽 경사(증가)는 완만하고, 왼쪽 낙하(감소)는 순간적이다. 시간 방향으로 보면 "천천히 오르고 한 번에 떨어진다".

## 사실 점검표
- 단위: cwnd는 바이트로도 MSS로도 쓴다. 화면에서 한 가지로 통일한다(MSS 권장).
- slow start는 "느린" 게 아니라 지수 증가다. 이름은 초기 값이 작아서 붙었다.
- 감소는 곱셈(×1/2), 증가는 덧셈(+1 MSS/RTT).
- 처리량 ≈ cwnd × MSS / RTT. (실제로는 rwnd와 min을 취한다.)
- 손 계산: MSS = 1460 B, RTT = 50 ms, 손실 시 cwnd = 64.
  - 최고점 처리량 = 64 × 1460 × 8 / 0.05 = 747,520 / 0.05 ≈ 14.95 Mbit/s.
  - 손실 후 ssthresh = cwnd = 32 → 32 × 1460 × 8 / 0.05 ≈ 7.48 Mbit/s.
  - 32에서 64까지 +1/RTT → 32 RTT = 1.6 s 걸림.
  - 톱니 평균 cwnd = (32+64)/2 = 48 → 48 × 1460 × 8 / 0.05 ≈ 11.2 Mbit/s (최고점의 75%).
  - 같은 손실이 타임아웃이면 cwnd = 1 → 약 0.23 Mbit/s에서 slow start로 재상승(1→2→4→…→32까지 5 RTT = 0.25 s, 이후 선형).
- slow start 예: 10→20→40→80 (RTT마다 2배). 80이 한계 초과라면 그 RTT 안에 손실이 난다.

## 흔한 오해와 깨는 순간
- 오해: "패킷이 손실되면 cwnd는 항상 1로 돌아간다."
- 깨는 순간: 독자가 손실 직후 cwnd를 예측해 고른 뒤 정답을 본다. 중복 ACK 손실은 64→32(절반)이고, 1로 가는 건 타임아웃일 때뿐이다. 두 경로의 궤적 차이를 같은 손실 시점에서 나란히 확인한다.

## 비트
1. slow start 구간: cwnd가 RTT마다 2배로 치솟는다(느리지 않다).
2. 예측 지점: cwnd = 64에서 손실이 난다. 독자는 다음 cwnd 궤적을 먼저 예측한다.
3. 공개: 중복 ACK면 32로 반감, ssthresh도 32. 타임아웃이면 1로 추락.
4. 반감 후 구간: 기울기가 slow start보다 훨씬 완만해진다(+1 MSS/RTT, 32 RTT 필요).
5. 톱니 반복: 평균 cwnd가 최고점의 약 75%라서 링크를 다 못 쓴다.
6. 진단 판단: 톱니가 32↔64로 규칙적이면 정상 AIMD, 바닥(1)까지 자주 무너지면 타임아웃 위주의 손실이라 처리량 저하의 원인이다.
