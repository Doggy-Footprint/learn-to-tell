# direction

## 초안 a
- 표현: 손으로 그린 SVG 트리. 칸 4개짜리 노드, 용량 초과 칸은 bad 색, 새 노드는 accent 테두리, 구분 키는 알약(chip)이 노드 사이를 움직이고, 노드는 transform으로 자리를 옮긴다. 7단계(S0~S6).
- 부합: 오른쪽 잎 먼저 생성 → 구분 키 → 부모 넘침 판단 순서, 새 루트가 마지막, 마지막에 모든 노드가 한 층 내려감, 잎 연결 리스트 점선, 잎 3+2·내부 2+1+2. 키 합계·자식 수도 맞다.
- 어긋남: 비트 5(꽉 차지 않은 부모에서 멈춤)와 6(페이지 크기)이 없다. "복사/이동"을 글로만 말하고 그림에서 86이 오른쪽 잎에 남는 것을 칩 외에 표시하지 않는다. 화면 결함 코드는 없다(audit 0건).

## 초안 b
- 표현: LTT.diagram + highlight, 단계마다 전체를 다시 그린다. 노드마다 "4/4", "5/4 넘침" 라벨, 8단계, 마지막에 페이지 크기 문장.
- 부합: 순서·사실은 맞고 8 KB/4 KB를 basis·recall에 넣었다. 어긋남: 노드가 매번 다시 그려져 움직임이 없고(전이가 안 보임), 대비 비트 5는 없으며, 페이지 크기는 글뿐이다. 화면 결함 코드는 없다(audit 0건).

## 가져올 것
- a: 커스텀 SVG 노드/칩/transform 이동 코드 전체와 S0~S6 상태.
- b: "n/4" 용량 라벨 아이디어, 마지막 단계에 페이지 크기 비트.

## 최종 방향
그림 하나: 높이 3 B+tree(루트·내부 I2·잎 L, 잎 연결 점선, 노드는 칸 4개 페이지). 비트: ① 경로 세 노드 모두 꽉 참 → ② 86이 잎에 들어와 5칸 넘침(빨강) → ③ 새 오른쪽 잎이 먼저 생기고 86이 복사되어 부모로 올라감 → ④ I2 넘침 → ⑤ I2가 갈라지고 80이 이동, 루트 넘침 → ⑥ 루트가 갈라지고 100이 올라감 → ⑦ 새 루트가 마지막에 생기고 모두 한 층 내려가 높이 4 → ⑧ 대비: 루트·I2가 여유 있으면 같은 삽입이 잎 분할 한 번으로 멈춤, 높이 그대로 → ⑨ 트리 대신 페이지 크기 막대(8 KB 팬아웃≈500 → 약 1.25억 키, 4 KB ≈ 250 → 약 1,560만 키). 조작은 단계 재생(덱 steps). 글은 노드 안 "n/4" 라벨, 단계 자막, takeaway(복사/이동, 팬아웃), basis(모델 수치).
