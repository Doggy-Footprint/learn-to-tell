# 방향: B+tree 분할 연쇄 (direction)

## 초안 점검

**a.html (3층 → 4층, 노드 id 보간).** 노드 id를 단계 사이에 이어 붙여 위치를 보간한다. 리프가 갈라질 때 옆 리프가 밀리고, 루트 분할 뒤 모든 노드가 한 층 내려가 깊이 +1이 움직임으로 보인다. 스토리보드와 어긋난 점: 리프 값이 `30,41,55`, `60,70,78`로 스토리보드(`30,40,50`, `60,70`)와 다르다. 루트 분할 단계에서 `RR`은 자식 표시 없이 "자식 3"만 적혀 있다. 트리 높이 표시가 없다. 화면 결함은 audit에서 찾지 못했다(고침 0건).

**b.html (격자 좌표, transform 보간).** 행 위치를 미리 비워 두고 노드를 옮긴다. 장점은 리프 줄과 행 배치가 깔끔하다는 점이다. 단점은 간선을 단계마다 새로 그려 간선이 튀어 나온다는 점이다. 4단계에서 새 루트가 빈 행에 나타날 뿐 깊이 증가가 움직임으로 드러나지 않는다. 노드 수가 많아 한 그림에 글이 많이 얹혔다.

**c.html (단계마다 DOM 재생성).** 리프 A~E를 고정 행에 두고 새 노드는 페이드인한다. 문제는 4단계와 5단계 사이 변화가 높이 라벨뿐이라는 점이다. 스토리보드 비트 5("모든 리프의 깊이가 함께 +1")가 움직임으로 없다. 또 새 루트 T가 리프 분할과 같은 단계에서 나타나 생성 순서("새 루트는 가장 나중")를 어긴다.

**d.html (LTT.diagram + 표시 단계표).** 6단계가 스토리보드 비트와 생성 순서(R 분할 → 새 루트 NR 마지막)에 가장 잘 맞는다. 간선 라벨 "25 복사 ↑", "60 이동 ↑", "200 이동 ↑"이 구분 키의 이동을 드러낸다. 사실 오류: 리프 L4가 `90 95 99`로 되어 있어 스토리보드(`90·95`)와 다르다. 노드가 `display` 토글로 켜지고 꺼져 이동이 없다. 깊이 +1도 움직임이 아니다.

## 가져올 것
- a의 노드 id 보간과 `lv` 변화 방식을 쓴다. 깊이 +1을 모든 노드가 한 층 내려가는 움직임으로 보인다. 단계 시작 때 새 노드를 나눠 준 부모 자리에서 출발시키는 `from` 개념은 a에 없고 새로 넣는다(리프가 갈라져 나오고, N2가 N2a·N2b로 갈라지고, R이 RL·RR로 갈라진다).
- a의 기대값 `LTT.expect(500 ** 3, 1.25e8)`과 basis 문장을 그대로 쓴다.
- d의 간선 라벨 아이디어는 쓰지 않는다(상자 안 상태 태그로 대체해 간선을 깨끗이 둔다). d의 "단계표" 대신 노드 id 보간을 쓴다.
- 리프 줄은 6칸 고정 슬롯으로 둔다. 리프가 갈라지면 새 리프가 옆 칸에 미끄러져 나오고, 기존 리프는 한 칸씩 밀린다.
- 스토리보드 값은 그대로 쓴다(`10,20,22,28` / `30,40,50` / `60,70` / `80,85` / `90,95`).
- 비트는 스토리보드 5개를 6단계로 쪼갠다: 루트 분할과 새 루트 생성을 분리해 생성 순서를 드러낸다.

## 최종 방향
**그림 뼈대.** 세로 3층(루트, N2 계열 내부 노드, 리프 줄)으로 시작하는 SVG 트리. 리프 줄은 6칸 슬롯이고 리프끼리 점선 형제 링크로 이어진다. 오른쪽 끝에 "나머지 자식" 점선 상자 하나. 왼쪽 위에 "트리 높이 3/4" 표시. 노드 상자는 키 한 줄(모노스페이스)과 상태 한 줄로 이뤄진다.

**비트별 움직임 (생성 순서대로).**
0. 25 삽입 표시(리프 아래 ▲). 루트·N2·리프 A(10,20,22,28)가 굵은 선으로 강조되어 "경로 세 노드가 모두 4키로 가득"을 보인다.
1. 리프 A가 `10,20,22,25,28`로 5키가 되어 빨간 상자로 넘친다.
2. 리프 A가 갈라진다. 새 리프 `25,28`이 A에서 미끄러져 나와 옆 칸에 자리 잡고, 나머지 리프가 한 칸씩 밀린다. N2가 5키로 넘친다(상태 "25 받음"). 새 리프 상태 "25 복사".
3. N2가 N2a(`25,30`)와 N2b(`80,90`)로 갈라져 N2 자리에서 좌우로 나온다. 루트가 5키로 넘친다(상태 "60 받음"). 60은 이동이라 아래에 남지 않는다.
4. 루트가 RL(`60,100`)과 RR(`300,400`)로 갈라져 좌우로 나온다. 가운데 200이 칩(강조된 작은 상자)으로 한 층 위에 올라온다.
5. 200 칩이 "새 루트"가 되어 맨 위에 자리 잡고, 나머지 노드 전체가 한 층 내려간다(깊이 +1). 트리 높이 3 → 4.

**조작.** 없음. 단계 자막 버튼만 쓴다. 움직임은 자막 단계 전환 때 한 번씩 보간된다(반복 재생은 kit이 맡는다).

**글.** 덱 제목은 주장 문장("분할은 아래에서 위로 번지고, 루트가 갈라질 때만 트리가 한 층 자란다"). 부제는 "삽입 키 25의 경로. 노드는 최대 4키이고, 리프끼리 오른쪽 형제 링크(점선)로 이어진다." 자막은 6개(①~⑤ 번호 포함). 요약 takeaway와 recall(페이지 4KB→8KB의 키 수 배율, 답 8), basis(모델 계산 태그 포함)는 스토리보드 문장을 따른다. 용어는 `{{리프}}`, `{{팬아웃}}` 두 개만 표시한다.
