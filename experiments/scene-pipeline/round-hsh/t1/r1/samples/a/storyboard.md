# 스토리보드: B+tree 노드 분할이 루트까지 전파

## 독자가 말할 수 있어야 할 한 문장
꽉 찬 리프에 키를 넣으면 리프가 둘로 갈라지고, 부모도 꽉 차 있으면 한 단계씩 위로 같은 분할이 번져서, 루트까지 꽉 찼을 때만 새 루트가 위에 생겨 트리 높이가 1 커진다.

## 인과 사슬
1. 키가 들어갈 리프를 찾는다(루트에서 아래로 탐색).
2. 리프가 가득 차 있다(페이지 용량 초과) → 리프 분할: 새 리프(오른쪽 형제) 생성, 키 절반 이동.
3. 새 리프를 가리킬 구분 키가 부모에 들어간다 → 부모가 가득 차 있으면 부모도 초과.
4. 초과한 내부 노드 분할: 새 내부 노드 생성, 가운데 키가 한 층 위로 올라간다.
5. 같은 일이 조상마다 반복. 루트가 초과하면 루트가 분할되고, 둘을 가리키는 새 루트가 맨 위에 생긴다 → 높이 +1.

## 화면에 꼭 보일 것
- 높이 3 트리: 루트, 내부 노드 N2, 리프 줄(리프끼리 오른쪽 형제 링크 포함).
- 경로상의 노드 3개가 전부 가득 참(각 4키)이라는 사실, 삽입 키 25의 경로.
- 분할 때마다 위로 올라가는 구분 키 하나(25 → 60 → 200).
- 강조점 하나: 분할이 아래에서 위로 한 층씩 번지다가 새 루트에서 멈추는 연쇄.

## 생성 순서 (틀리기 쉬움)
- 리프 분할이 먼저, 부모 분할이 그다음, 루트 분할이 마지막. 아래에서 위로.
- 새 루트는 가장 나중에 생기고, 가장 위에 놓인다. 기존 노드는 아래로 밀려나는 게 아니라 깊이가 모두 같이 1 늘어난다.
- 분할로 생긴 새 노드는 원래 노드의 오른쪽 형제다.

## 사실 점검표
- 가정: 노드당 최대 4키(자식 최대 5). 5키가 되면 초과.
- 리프 분할은 구분 키를 **복사**해 올린다(25는 오른쪽 리프에도 남음). 내부 노드 분할은 가운데 키를 **이동**한다(60, 200은 아래 노드에서 사라짐).
- 손 계산 ① 리프 [10,20,22,28]에 25 삽입 → 정렬 10,20,22,25,28(5키) → 왼쪽 [10,20,22], 오른쪽 [25,28], 25 복사 상승.
- ② N2 [30,60,80,90]에 25 삽입 → [25,30,60,80,90](5키, 자식 6) → 60 이동 상승, 왼쪽 [25,30](자식 3), 오른쪽 [80,90](자식 3). 2+2+1=5키 ✓.
- ③ 루트 [100,200,300,400]에 60 삽입 → [60,100,200,300,400](5키, 자식 6) → 200 이동 상승, 왼쪽 [60,100](자식 3), 오른쪽 [300,400](자식 3), 새 루트 [200](자식 2). 높이 3→4.
- 키 총수 변화: 리프 분할 후 키 값 25가 중복(리프+내부), 내부 분할은 키 수 보존.
- 새 루트는 키 1개, 자식 2개만 있어도 되는 유일한 노드(루트는 최소 점유 예외).
- 페이지 크기 감각(근사): 8KB 페이지, 키+포인터 약 16B → 팬아웃 약 500. 500³ ≈ 1.25억 키가 높이 3(루트→내부→리프)에 들어간다. 4KB면 팬아웃 약 250, 250³ ≈ 1,600만.
- 높이는 분할이 루트까지 갈 때만 커진다. 대부분의 삽입은 리프 하나에서 끝난다.

## 흔한 오해와 깨는 순간
- 오해: "트리는 리프 쪽으로 깊어지며 자란다" 또는 "삽입 한 번이면 늘 루트까지 바뀐다."
- 깨는 순간: 루트가 분할되며 맨 위에 새 노드가 생기고 모든 리프의 깊이가 동시에 1 늘어난다. 반대로 부모에 빈자리가 있으면 연쇄가 그 층에서 멈춘다(균형은 항상 유지).

## 비트
1. 25가 들어갈 리프가 [10,20,22,28]로 꽉 차 있고, 부모와 루트도 꽉 차 있다.
2. 리프가 5키가 되어 둘로 갈라지고, 25가 복사되어 위로 올라간다.
3. 부모 N2가 5키로 넘쳐 분할되고, 60은 복사가 아니라 이동한다.
4. 루트도 넘쳐 분할되고, 200이 올라가며 새 루트가 맨 위에 생긴다.
5. 모든 리프의 깊이가 함께 +1. 페이지가 클수록 팬아웃이 커서 이런 연쇄가 드물고 트리가 낮다.
