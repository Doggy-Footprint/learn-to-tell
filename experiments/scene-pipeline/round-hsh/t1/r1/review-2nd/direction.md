# direction

## 초안
- a: 노드를 SVG 상자로 두고 단계마다 위치를 보간해 움직인다. 선은 노드를 따라 매 프레임 다시 그린다. 꽉 참(회색)·초과(빨강)·새 노드(accent)를 색과 라벨로 가른다. 5단계가 생성 순서(리프 → N2 → 루트 → 새 루트, 리프 깊이 +1)와 맞고 25 복사, 60 이동 설명도 맞다. 어긋난 점: 마지막 단계에서 "나머지 자식" 노드가 사라지고 루트 오른쪽 가지에 자식이 없다. 25가 복사라는 것이 그림에 따로 드러나지 않고 자막에만 있다. 화면 결함은 없다(audit 0건).
- b: CSS transform transition으로 노드가 미끄러지고, 선은 최종 위치에서 다시 그린다. 높이 라벨이 3 → 4로 바뀐다. 생성 순서는 맞다. 어긋난 점: 노드가 움직이는 중에는 선이 이미 최종 위치라 어긋나 보인다. 경로 강조(hot)가 단계마다 일관되지 않다. 키 이동 표시가 없다.
- c: 경로 노드를 accent로 칠하고, 형제 링크를 화살표로 그린다. 새 노드마다 "새 노드" 태그를 붙인다. 순서는 맞다. 어긋난 점: 3단계에서 새 루트와 두 자식이 한꺼번에 생기고 4단계에서야 "높이 4"라고 말해 깊이 증가가 한 박자 늦다. 리프 줄에 키 수가 다른 상자가 섞여 읽기 어렵다.
- d: `LTT.diagram`에서 요소를 단계별로 켜고 끈다. "25 복사 ↑", "60 이동 ↑", "200 이동 ↑" 라벨 화살표로 복사와 이동을 구분한다. 어긋난 점: 리프 [90,95,99]처럼 스토리보드에 없는 키가 있다. 노드가 켜지고 꺼질 뿐 움직이지 않아 "깊이가 같이 늘어난다"가 보이지 않는다. 라벨이 격자 안에서 서로 겹치기 쉽다.

## 가져올 것
- a의 노드 보간 + 선 추종 코드와 5단계 구성, 색 구분(가득/초과/새 노드).
- d의 "복사 ↑ / 이동 ↑" 라벨 아이디어: 받는 노드 옆에 알약 표식으로 둔다.
- c의 "트리 높이 N" 표시, b의 높이 라벨.
- 새로 고칠 것: 마지막 단계에서도 "나머지 자식"을 유지하고, 스토리보드에 없는 키는 쓰지 않는다.

## 최종 방향
그림 하나: 높이 3 트리가 화면 가득 있고 맨 아래 리프 줄은 형제 링크로 이어진다. 비트 0은 경로의 세 노드(루트·N2·리프 [10,20,22,28])가 4키로 가득 차 있고 25가 리프 아래에서 들어갈 자리를 가리킨다. 비트 1은 리프가 5키가 되어 빨갛게 넘친다. 비트 2는 리프가 둘로 갈라져 오른쪽에 새 리프 [25,28]이 생기고, "25 복사 ↑" 표식이 N2 옆에 붙으며 N2가 5키로 넘친다. 비트 3은 N2가 둘로 갈라져 새 내부 노드가 오른쪽에 생기고 "60 이동 ↑" 표식이 루트 옆에 붙으며 60이 N2에서 사라지고 루트가 넘친다. 비트 4는 루트가 갈라지고 "200 이동 ↑"과 함께 새 루트가 맨 위에 생기며 모든 노드가 부드럽게 한 층 내려가 높이가 3 → 4가 된다. 조작은 단계 이전/다음과 반복 재생(figure steps)이다. 글은 단계 자막, 노드 안의 키와 상태 라벨, 높이 표시, 페이지 크기 근거(basis)만 얹는다.
