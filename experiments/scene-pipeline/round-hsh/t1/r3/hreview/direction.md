# direction.md: B+tree 노드 분할 (t1/r3)

## 1. 초안 검토

- a.html: `LTT.diagram` 격자에 루트·잎 2층을 그리고, 단계마다 노드 내용을 다시 그린다. 52 삽입 → 잎 분할 → 루트 분할 → 새 루트 순서와 키·자식 수(루트 5키·자식 6, 분할 뒤 2키·자식 3씩)는 점검표와 맞다. 결함: `layout(s)`의 `tone`이 `s === 5`일 때 모든 노드에 적용돼, 마지막 단계에서 잎과 루트가 전부 초록 테두리가 된다(판정색 오용). 움직임은 노드 교체뿐이라 "잎이 새로 생긴다"와 "층이 위에 더해진다"가 보이지 않는다. audit: 고침 0건.
- b.html: `LTT.diagram` 격자 + `send` 패킷 + 잎 연결 `ortho` 엣지. 복사 엣지(`cu4`, `cu5`)를 점선으로 그리고, "복사는 잎에 남고 내부 노드는 이동" 차이를 캡션에 정확히 적었다. 결함: 두 크기 모두 장면1에서 그래프 겹침 1건(라벨·노드·엣지 5곳)이 잡혔다. 단계별 상태 교체라 생성 순서는 맞지만 움직임이 약하다. audit: 고침 2건.
- c.html: 누적 빌드 구조가 생성 순서와 맞는다. 잎 자리는 고정, 새 대상만 `fresh`로 `ltt-in`이 돌고, 넘친 칸은 `ov`로 표시된다. 잎 연결은 아래로 굽는 곡선. 결함: a와 같은 `tone` 버그(`s === 5`에 전 노드 초록). 복사 올림을 움직임으로 보이지 않는다(패킷 없음). audit: 고침 0건.
- d.html: 다섯 상태를 겹쳐 두고 단계마다 한 장만 켠다. 루트 위 "위 층 없음" 회색 자리는 새 루트가 올 곳을 미리 보여 준다. 결함: 상태 사이가 페이드라 분할이 일어나는 과정이 안 보이고, 상태 3에서 MID가 이미 내부 노드 위에 떠 있어 "위로 이동"의 순서가 건너뛰어진다. audit: 고침 0건.

## 2. 가져올 것

- c: 누적 빌드 구조(`frame(st)` 한 함수, 단계마다 다시 그리고 `fresh` 목록의 대상만 나타남), 넘친 칸 `ov`·`over` 표시, 잎 아래 연결 곡선, 잎 칸 고정 자리.
- d: 할당 전 빈 잎 자리를 점선 자리로 보인다(슬롯 3). 새 잎이 어디에 생기는지 미리 보인다.
- b: "복사는 잎에 남고, 이동은 사라진다"는 판단을 캡션 문장으로 쓴다. 올라가는 키는 패킷 대신 칩이 위로 올라가는 CSS 움직임으로 보인다.
- 수치: a·b·c·d가 모두 맞게 쓴 점검표 값(잎 5키 → 2+3, 루트 5키 → 2+1+2, 자식 6 → 3+3)을 그대로 쓴다.
- 버린 것: `tone` 판정색 로직(a·c 공통 결함), 엣지 라벨 배치(b의 겹침 원인).

## 3. 최종 방향

그림 뼈대: 잎 여섯 칸을 한 줄로 둔다(슬롯 0~5, 슬롯 3은 할당 전 점선 빈 자리). 그 위에 루트 한 줄, 맨 위에 새 루트가 올 빈 행. 잎끼리는 아래로 굽는 점선 화살표로 잇는다. 높이 표시는 오른쪽 위.

비트별 움직임(생성 순서대로):
1. 잎 A [40 45 50 55]와 루트 [20 40 60 80]이 있다. 52가 A에 들어가 다섯째 칸(55)이 붉게 넘친다.
2. 빈 자리에 새 잎 B가 나타나 [50 52 55]를 받는다. 50 칩이 B 위에서 루트 쪽으로 올라간다. A·B 모두 50을 가진 채 남는다.
3. 루트에 50이 들어와 5칸이 되어 넘친다(붉은 테두리). 루트에서 B로 가는 간선이 생긴다.
4. 루트가 내부 노드 I1 [20 40]과 I2 [60 80]으로 갈라진다. 가운데 50 칩이 위로 이동한다.
5. 맨 위 행에 [50] 새 루트가 나타나고, 높이는 "3". 모든 잎은 같은 깊이라는 표시가 붙는다.

조작: 없음. 여섯 단계를 덱 버튼으로 넘긴다. 판정색은 넘침 표시에만 쓴다.
