# direction

## 초안 분석

**a**: 노드 `<g>`를 고정 DOM으로 두고 translate transition으로 잎이 옆으로 밀리는 움직임을 낸다. 잎 사이 곡선 화살표, 키 칸 강조가 좋다. 어긋남: 마지막 두 단계에서 분할된 내부 노드 A·B와 새 루트 NR이 `s===4`에 한꺼번에 나타나 "새 루트는 가장 마지막" 순서를 깬다. 잎 키가 복사/이동 구분 없이 같은 모양. 루트 분할 단계의 "50 이동"은 캡션으로만 말한다. audit 0건.

**b**: `LTT.diagram` + 노드/엣지 id 목록으로 단계마다 통째로 다시 그린다. `send`로 50이 부모로 올라가는 패킷을 보인다. 사실은 맞으나 상자 라벨이 숫자 문자열이라 키 칸이 안 보이고, 엣지 30여 개를 손으로 적어 겹침 5곳(graph-overlap)이 남았다. 화면 결함.

**c**: 손으로 짠 SVG에 키 칸, 용량 초과 칸(점선 빨강), 새 잎 태그, 잎 연결 포인터, 층 이름, 높이 표시를 그리고 새로 생긴 것만 fade-in. 루트 분할 단계에서 가운데 키 50이 칩으로 "위로 이동" 하며 두 내부 노드가 생기고, 다음 단계에서야 새 루트가 생겨 생성 순서가 정확하다. 복사 올림은 캡션으로만 보이고 어디서 어디로 가는지 선이 없다. 규모(8KB, 팬아웃 500) 비트가 없다. audit 0건.

**d**: 상태 5장을 겹쳐 두고 opacity 전환. 순서와 사실은 맞고 "위 층 없음" 자리 표시가 좋다. 하지만 전환이 전체 교차 페이드라 무엇이 새로 생겼는지 안 보이고, 잎 이동 같은 움직임이 없다. audit 0건.

## 가져올 것
- c의 SVG 구조(키 칸, 초과 칸, 새 잎 태그, 연결 포인터, fresh만 애니메이션, 50 칩)를 뼈대로 쓴다.
- d의 "위 층 없음" 아이디어는 쓰지 않고, c의 층 이름 라벨로 충분하다.
- b의 "패킷으로 올라감" 아이디어를 복사 올림 점선 경로로 옮긴다.
- 규모 비트는 새로 추가한다.

## 최종 방향
뼈대: 트리 하나(루트·내부·잎 3층 격자)가 화면 전체. 잎 아래에 연결 포인터, 왼쪽에 층 이름과 높이.
움직임(6단계, 생기는 순서대로): ① 가득 찬 잎 [40 45 50 55] 강조 ② 52 칸이 생겨 5키, 빨강 초과 ③ 새 오른쪽 잎 N이 생기고 키 절반 이동, 포인터 재연결 ④ 50이 N에서 루트로 점선 "복사" 경로를 타고 올라가 루트가 5키 초과 ⑤ 루트가 [20 40]·[60 80]으로 갈라지고 50 칩이 "이동"하며 위로 뜸 ⑥ 맨 위에 [50] 새 루트가 생기고 높이 2→3 ⑦ 같은 트리 위에 규모 환산(8KB, 팬아웃 ~500, 3층 ≈ 1.25억 키)이 얹힘.
조작: 단계 재생(이전/다음/반복). 글: 단계 자막, 글 속 라벨은 한두 단어, basis에 가정 표기.
