# B+tree 노드 분할 — 스토리보드

## 독자가 말할 수 있어야 하는 한 문장
"가득 찬 잎에 키를 넣으면 잎이 둘로 쪼개지고 구분 키가 부모로 올라가며, 부모도 가득 차 있으면 같은 일이 위로 연쇄되어 루트까지 가면 새 루트가 생겨 트리 높이가 1 늘어난다. 높이는 아래가 아니라 위에서 늘고, 그래서 모든 잎은 항상 같은 깊이다."

## 인과 사슬
1. 키가 들어갈 잎 페이지가 이미 가득 참(용량 초과) →
2. 잎을 둘로 나눔(새 오른쪽 형제 페이지 할당, 키 절반 이동) →
3. 오른쪽 잎의 첫 키가 구분 키로 부모에 삽입 필요 →
4. 부모도 가득 차 있으면 부모가 초과 → 부모 분할 →
5. 부모 분할의 가운데 키가 다시 조부모로 올라감 → … 반복 →
6. 루트가 초과하면 루트 분할, 가운데 키만 가진 새 루트 생성 → 높이 +1.
분할은 "가득 참"이 연속된 경로(잎→루트)에서만 전파된다. 중간에 여유 있는 조상이 있으면 거기서 멈춘다.

## 화면에 꼭 보일 것
- 대상: 잎 페이지(키 슬롯, 용량 칸), 내부 노드(키+자식 포인터), 루트, 잎 사이 연결 리스트(형제 포인터), 새로 할당된 페이지.
- 관계: 부모 키 ↔ 자식 구간, 구분 키가 어느 자식에서 왔는지, 분할 전후 슬롯 수.
- 강조점 하나: 분할이 잎에서 루트까지 올라가는 경로(그리고 마지막에 루트 위에 새 루트가 얹히는 순간).

## 생성 순서 (틀리기 쉬움)
1. 새 키가 잎에 들어가 초과 상태(5개)가 먼저 생긴다 → 그다음 분할.
2. 새 오른쪽 잎이 먼저 만들어지고 키가 옮겨진 뒤, 그 구분 키가 부모에 들어간다(아래 → 위).
3. 부모는 구분 키를 받은 뒤에야 초과가 드러나고 분할된다. 위 노드는 아래 분할의 결과를 받아서 바뀐다.
4. 새 루트는 가장 마지막에 생긴다. 기존 루트는 사라지지 않고 두 내부 노드로 갈라진다.
5. 트리는 "아래가 늘어나는" 것이 아니라 "맨 위에 층이 추가"된다. 모든 잎이 한꺼번에 한 칸 내려간 효과.

## 사실 점검표 (페이지당 최대 키 4개, 내부 노드 자식 최대 5개로 가정)
- 잎 분할: 키 5개 → 왼쪽 2 + 오른쪽 3. 구분 키는 오른쪽 잎의 첫 키를 **복사**해 올림(잎에는 그대로 남음. 데이터는 잎에만 있음).
- 내부 노드 분할: 키 5개(자식 6개) → 왼쪽 2키(자식 3) + 가운데 키 1개 위로 **이동**(원래 노드에 안 남음) + 오른쪽 2키(자식 3). 키 2+1+2=5, 자식 3+3=6 ✓.
- 잎은 복사 올림, 내부 노드는 이동 올림. 이 차이가 가장 흔한 실수.
- 잎 연결 리스트: 새 잎은 원래 잎의 다음 포인터를 물려받고 원래 잎이 새 잎을 가리킨다(범위 스캔 유지).
- 구체 예시 손 계산:
  - 시작: 루트 [20,40,60,80](가득), 자식 5개. 세 번째 잎 [40,45,50,55](가득).
  - 52 삽입 → 잎 [40,45,50,52,55] 초과 → 왼쪽 [40,45], 오른쪽 [50,52,55], 50 복사 올림.
  - 루트 [20,40,50,60,80] 5키(초과) → 가운데 50 이동: 왼쪽 [20,40](자식 3: [..],[20..],[40,45]), 오른쪽 [60,80](자식 3: [50,52,55],[60..],[80..]).
  - 새 루트 [50], 자식 2개. 높이 2층 → 3층. 잎 깊이는 전부 3으로 동일.
- 수치 규모(실제 페이지): 8KB 페이지, 키 8B + 포인터 8B ≈ 16B → 8192/16 = 512, 헤더 빼면 약 500 팬아웃(근사). 분할 직후 노드는 약 절반(~250) 찬 상태. 3층이면 500³ ≈ 1.25×10⁸ 키 수용. 키가 길어질수록 팬아웃이 줄어 높이가 빨리 늘어난다.
- 루트 분할은 극히 드묾: 팬아웃이 수백이라 높이는 거의 안 변함. 대부분의 삽입은 분할이 없거나 잎 한 번에서 끝난다.

## 흔한 오해와 깨는 순간
- 오해: "분할은 가득 찬 그 노드 하나만의 일이고, 트리는 BST처럼 아래쪽에 잎이 달려 깊어진다."
- 깨는 순간: 52 삽입 한 번에 잎 → 내부 노드 → 루트가 연쇄 분할되고, 새 루트가 위에 생기며 모든 잎이 동시에 한 층 내려가는 순간. 불균형 없이 높이가 늘어난다.

## 비트
1. 가득 찬 잎에 52가 들어가 5번째 칸이 모자람 — 초과가 분할의 원인.
2. 잎이 [40,45] / [50,52,55]로 갈라지고 50이 복사되어 부모로 올라감(잎에도 남음).
3. 부모(루트)도 가득 차 있어 초과 → 가운데 50이 이동(복사 아님)하며 내부 노드가 둘로 갈라짐.
4. 위로 올릴 부모가 없으니 [50] 하나뿐인 새 루트가 생김 — 높이 2→3, 모든 잎이 같은 깊이 유지.
5. 규모 환산: 8KB 페이지 팬아웃 ~500이면 3층에 ~1.25억 키, 루트 분할은 거의 안 일어남. 페이지 크기·키 길이가 팬아웃, 곧 높이를 정한다.
