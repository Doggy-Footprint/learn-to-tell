# 검수: 가비지 컬렉션 방식 (scene.html)

캡션 번호는 scene.html의 CAPS 순서(①~⑦)다. 스크린샷 이름 옆 괄호가 그 캡션이다.

| 항목 | 판정(통과/실패) | 근거(스크린샷 이름 또는 코드 위치) |
| --- | --- | --- |
| 사실: 연결 직후 A = x + B.peer = 2, B = y + A.peer = 2 | 통과 | scene-step1(②): 카운트 2, 2 |
| 사실: x 해제 → A = 1, y 해제 → B = 1, 둘 다 0 아님 | 통과 | scene-step2(③): 카운트 1, 1, x·y 해제 표시 |
| 사실: 해제 후 루트 경로 0개 | 통과 | scene-step3(④) 왼쪽 "루트 경로: 없음" |
| 사실: mark 결과 표시 0, sweep 대상 2 (A, B) | 통과 | scene-step3(④) "mark: 루트 0개 … 표시 0개", scene-step4(⑤) "sweep: 미표시 A, B 해제" |
| 사실: 순환 없는 x→A 단독 비교 | 통과 | 화면에 없음. 틀린 주장도 없음 |
| 사실: 카운트는 들어오는 참조 수 (A.peer=B는 B를 올림) | 통과 | scene-step1(②): 화살표 A→B(파랑), B→A(빨강). scene.html:74-77 |
| 사실: 순환이어도 tracing에서는 누수 아님, 순환 없어도 루트에서 닿으면 누수 | 통과 | scene-step5(⑥): 객체 C "순환 없음 · 표시됨 → 남음" |
| 사실: 스냅샷은 정지 시점, V8은 취득 전 GC | 통과 | 화면에 없음. 틀린 주장도 없음 |
| 사실: CPython은 순환 탐지 GC 추가, JVM·V8·Go는 tracing | 통과 | scene-t1s: 근거 문구(basis) |
| 생성 순서: 객체 생성 → 변수 연결 → 객체끼리 연결 → 변수 해제 | 통과 | scene-t1s(①) peer: null, 카운트 1 → scene-t4s(②) peer 연결 → scene-step2(③) 해제 |
| 생성 순서: 카운트는 연결 시 오르고 해제 시 내림 (1 → 2 → 1) | 통과 | scene-t1s(①), scene-t4s(②), scene-step2(③) |
| 생성 순서: mark가 sweep보다 먼저 보임 | 통과 | scene-step3(④): 미표시 + mark 줄만, sweep 줄 없음. scene-step4(⑤)에서 sweep 등장 |
| 생성 순서: 회수는 GC 사이클에서 일어남 | 통과 | scene-step2(③) "GC 사이클이 돌기 전: 아직 아무것도 안 치움" |
| 비트 1: 같은 A↔B 순환, 카운트 2·2 | 통과 | scene-step1(②). 스토리보드 비트 1은 "동시"로, 생성 순서 절은 "연결 → 순환"으로 적어 서로 어긋난다. 화면은 생성 순서를 따른다 |
| 비트 2: x, y 해제, 카운트 1 (0 아님) | 통과 | scene-step2(③) |

| 비트 4: mark에서 A, B 미도달, sweep이 치움 | 통과 | scene-step4(⑤) |
| 비트 5: 순환 없는 C가 전역 cache로 루트 경로에 남음 | 통과 | scene-step5(⑥) |
