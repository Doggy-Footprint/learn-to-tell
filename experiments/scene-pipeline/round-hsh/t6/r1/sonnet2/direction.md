# direction

## 초안 a
LTT.diagram 그래프 두 벌(RC / M&S)을 나란히 두고 player 하나로 7단계를 함께 넘긴다. 움직임은 `highlight`로 노드를 밝히는 것뿐이고, 카운트와 mark는 그림이 아니라 아래 글줄(`ltt-basis`)에만 있다.
- 순서: A 생성 → B → B.prev → C → 루트 해제 → mark → sweep. 점검표와 맞다(A=2,B=1 → 루트 해제 후 A=1).
- 어긋남: 루트→A 간선이 해제 뒤에도 그림에 그대로 남아 "끊겼다"가 안 보인다. M&S 쪽 A·B가 sweep 뒤에도 노드로 남고 흐려질 뿐이다. 코드 결함은 없다(audit 0건).

## 초안 b
같은 그래프 두 벌에 각자 player를 두고, 객체별 상태를 칩(`ltt-tag`)으로 그림 아래에 줄 세운다. 생성 단계에서 `send` 패킷이 간선을 따라 간다. RC 칩에 "A 참조 2"처럼 카운트가 있고 M&S 칩에 mark/해제가 있다.
- 순서: 생성 순서와 수치 모두 맞다. 해제 비트에서 RC와 M&S가 서로 다른 player라 두 쪽이 어긋날 수 있다. 카운트가 노드에서 떨어진 칩이라 눈이 오간다. 루트 간선이 남는 점은 a와 같다. audit 0건.

## 가져올 것
- a: 그래프 spec(루트·A·B·C, next/prev 간선), 한 컨트롤이 양쪽을 같이 넘기는 구조.
- b: 생성 단계마다 `send` 패킷으로 간선이 생기는 순간을 보이는 아이디어, 장면 제목 문구.

## 최종 방향
뼈대: 좌 RC, 우 M&S, 같은 격자 좌표의 객체 그래프. 단계마다 그래프를 새로 그려 노드 부제에 카운트(RC)와 mark(M&S)를 직접 얹고, 간선은 실제로 생길 때 나타나고 끊기면 점선 "끊음"으로 바뀐다.
비트: ①A 생성, 루트→A, A=1 ②A.next=B로 B 생성, B=1, 패킷이 A→B ③B.prev=A, A=2, 패킷이 B→A ④루트→C, C=1 ⑤루트→A 끊음, A=1·B=1, 순환 간선 강조(강조점) ⑥RC: 둘 다 0이 아니라 그대로 남음(노랑 아닌 bad 표시), M&S: 루트에서 mark, C만 mark ⑦M&S sweep으로 A·B 노드가 사라지고, RC 쪽 프로파일러 글줄에 "루트 경로 없음, 보유자는 서로뿐". mark가 sweep보다 먼저다.
조작: `LTT.stepper` 하나가 양쪽을 같이 넘기고 반복 재생. 글은 단계 자막과 각 그림 아래 한 줄 스냅샷 결과, takeaway/recall에 진단 판단(루트 경로 없이 남은 객체 → 순환 누수 의심, 해결은 순환 끊기·weak ref).
