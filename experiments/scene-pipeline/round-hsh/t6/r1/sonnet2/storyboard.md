# 스토리보드: 가비지 컬렉션 방식 (contrast)

대상: 애플리케이션 개발자 · 매체: 힙 스냅샷·메모리 프로파일러 · 결정: 메모리 누수 진단 · 테마: terminal

## 독자가 말할 수 있어야 하는 한 문장
"참조 카운팅은 객체 둘이 서로를 가리키면 카운트가 0이 되지 않아 순환 참조가 누수로 남고, mark-and-sweep은 루트에서 닿는지만 보므로 같은 순환도 수거한다. 그래서 힙 스냅샷에서 '루트에서 닿지 않는데 남은 객체'가 보이면 참조 카운팅 계열 누수를 의심한다."

## 인과 사슬
1. 같은 코드가 객체 A, B를 만들고 A.next=B, B.prev=A로 서로 연결한다.
2. 프로그램이 루트 변수(`root → A`)를 끊는다. 이제 프로그램은 A, B에 닿을 방법이 없다(도달 불가).
3. 참조 카운팅: 각 객체는 "나를 가리키는 참조 수"를 들고 있다. A는 B가, B는 A가 가리키므로 둘 다 카운트 1 → 0이 아니라 해제 안 됨 → 누수.
4. mark-and-sweep: 수거 시점에 루트에서 출발해 닿는 객체만 mark → A, B는 mark 안 됨 → sweep이 둘 다 해제.
5. 진단: 힙 스냅샷에서 retainer(보유 경로)를 따라가면, 참조 카운팅 쪽 A·B는 서로만 보유자이고 루트 경로가 없다.

## 화면에 꼭 보일 것
- 같은 객체 그래프 두 벌(RC / M&S): 루트, A, B, 보통 객체 C(루트에서 닿음).
- 객체별 참조 카운트 숫자(RC 쪽), mark 표시(M&S 쪽).
- 프로파일러 관점의 결과: 해제 후 남은 객체 목록과 보유 경로.
- 강조점 하나: 루트가 끊긴 뒤에도 A↔B 사이 간선이 카운트를 1로 붙들고 있는 순간.

## 생성 순서 (틀리기 쉬움)
- 객체 생성 시 카운트는 루트 참조로 1에서 시작한다. A 생성(A=1) → B 생성(B=1, 루트가 B도 잡는 경우도 있으나 여기선 A를 통해 생성) → A.next=B로 B=2 → B.prev=A로 A=2 → 루트 해제로 A=1.
- 루트 해제 직후 B는 여전히 2에서 시작하지 않도록 주의: 루트가 A만 가리킨다면 B의 카운트는 A.next 하나뿐이므로 B=1, 이후 B.prev=A로 A=2, 루트 해제 후 A=1.
- 아래 수치는 이 시나리오(루트는 A만 가리킴)로 통일한다.
- M&S는 mark 단계(루트에서 전파)가 먼저, sweep(mark 안 된 것 해제)이 나중이다. 순서가 뒤바뀌면 안 된다.

## 사실 점검표 (손 계산)
시나리오: 루트→A, A.next=B, B.prev=A, C는 루트→C.
- 생성 직후: A=1(루트), B=1(A.next), 그다음 B.prev=A로 A=2. C=1.
- 루트→A 해제: A=2−1=1, B=1. C=1 유지.
- RC 결과: A=1, B=1 → 둘 다 생존(누수 2개). C는 루트가 있으니 정상 생존.
- M&S 결과: mark={root, C}, 해제 대상={A, B} → 2개 해제.
- 카운트는 간선 수와 같다: 간선 A→B, B→A, 루트→C 해제 후 남은 참조 2개 = 카운트 합 A1+B1 = 2.
- RC는 카운트 0 즉시 해제(즉시성), M&S는 수거 주기 때만 해제(지연). 순환 여부와 별개의 차이임을 구분.
- 약한 참조(weak ref)로 B.prev를 걸면 A 카운트가 1에서 0이 되어 RC도 순환을 푼다(곁다리, 화면 필수 아님).

## 흔한 오해와 깨는 순간
- 오해: "GC가 있으면 안 쓰는 객체는 다 사라진다 / 서로 참조하는 객체는 M&S에서도 누수다."
- 깨는 순간: 루트를 끊은 뒤 RC 쪽 A·B 카운트가 1로 멈춰 남고, 바로 옆 M&S 쪽에서는 같은 A·B가 mark되지 않아 sweep에서 사라지는 장면. "카운트가 0이 아니다"와 "루트에서 닿지 않는다"가 다른 질문임을 드러낸다.

## 비트
1. 같은 그래프: 루트→A⇄B, 루트→C. 두 방식 모두 지금은 전부 살아 있음.
2. 카운트 표시: A=2, B=1, C=1. 카운트는 들어오는 간선 수.
3. 루트→A 해제: 프로그램은 A, B에 더 이상 닿지 못함. A=1, B=1.
4. RC 쪽: 둘 다 0이 아니므로 그대로 남음. 프로파일러에 닿지 않는 2개가 쌓이는 누수로 보임.
5. M&S 쪽: 루트에서 mark(C만), 이어서 sweep이 A, B 해제.
6. 진단 판단: 스냅샷에서 루트 경로 없는 객체 잔류 → 순환 참조 누수 의심, 해결은 순환 끊기 또는 weak ref.
