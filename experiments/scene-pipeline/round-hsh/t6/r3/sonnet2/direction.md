- 점검표 대비: 객체 생성 → B 생성 → A→B → B→A → 루트 해제 순서와 rc 2→1 계산이 맞다. 어긋난 점: mark 톱니가 12쌍 주기(5~16 MB)라 점검표의 16쌍·4~20 MB와 다르고, 루트 B 선이 B 생성 전부터 보인다. 전역 캐시 반전 없음. GC 표시가 120ms 창이라 거의 안 보인다.
- 결함 코드: `LTT.expect`가 12쌍 가정을 굳힌다. audit은 깨끗하다.

## 최종 방향
b의 뼈대를 고친다. 좌 참조 카운팅, 우 mark-and-sweep. 각 쪽은 그래프(주인공) 아래에 힙 타임라인과 스냅샷 두 줄. 비트: ① A 생성(rc 1), B 생성(rc 1; 루트→B 선도 이때) ② A.peer=B로 B rc 2, B.peer=A로 A rc 2, 순환 완성 ③ 루트가 손을 뗀다: 카운팅은 rc 1,1에서 멈춤, mark는 변화 없음(지연) ④ 100쌍 반복: 카운팅 힙은 4→104 MB 직선, mark는 16쌍마다 GC로 20→4 MB 톱니. GC 순간 쌍이 붉게 흐려지며 회수된다 ⑤ 끝나면 스냅샷: 카운팅은 Pair 200개·보유 경로가 서로뿐 ⑥ 반전: mark 쪽 버튼 "전역 캐시가 A를 쥐게 한다"를 누르면 mark 쪽이 처음부터 다시 돌며 캐시→A 화살표가 있어 GC가 돌아도 회수되지 않고 힙이 올라가고, 보유 경로가 루트 → 캐시 → A로 이어진다. 글은 그림 라벨, 단계 자막, 스냅샷 줄, 짧은 narration만. 수치에는 "모델로 계산한 예시" 태그와 basis.
