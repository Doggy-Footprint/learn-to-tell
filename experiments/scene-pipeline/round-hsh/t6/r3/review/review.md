# 검수: 가비지 컬렉션 방식 (contrast)

대상: scene.html. 스크린샷 t1s(0s)·t4s(4s)·t8s(8s). 프레임 4·5·6·7·8은 t8s 전후로 코드 좌표로 확인했다. 직전 audit은 고침 0건, 권고 1건(unused-term).

## 사실 점검표

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| 카운트 손계산: 최종 A=1, B=1 | 통과 | scene.html `graph()` rc = 루트 + 들어오는 참조. 프레임 4에서 둘 다 1 (`CAP.count[4]`) |
| 수치 예: 쌍 1 MB, 100쌍 100 MB | 통과 | `heapOf`, `LTT.expect("카운팅 100쌍 누수 MB")` (scene.html:23-31) |
| mark 톱니: 기준선 4 MB, 16쌍 주기, 최대 약 19~20 MB | 통과 | `LTT.expect("mark 톱니 최저")`, `GC_EVERY = 16` |
| 화살표 방향 | 통과 | mark 엣지는 루트에서 나감, count 엣지는 peer만 |
| 카운팅 장점: 즉시 해제, 승패 구도 없음 | 통과 | `CAP.count[4]` "rc는 즉시 2 → 1로 줄고 멈춘다", 좌우 대등 배치 |
| CPython 순환 감지기 명시 | 통과 | `basis`, 하단 각주 (t1s, t4s, t8s 하단에 보임) |

## 요약
실패 5건(비트 6, 도식 가독성, peer 라벨 겹침, 바 잘림, retainer 용어 노출). 모두 Edit로 고쳤다.

## 고친 것
- 비트 6: 반전 프레임의 `root→cache` 직선이 A 모서리를 지나던 것을 직각선(`ortho`, 오른쪽→아래)으로 바꿔 A·B 사이 빈 틈을 지나게 함.
- 읽을 수 없는 글: 도식 `cell`·`node`를 [190,120]/[140,58]에서 [126,96]/[116,52]로 줄여 확대 비율을 올림.
- 겹침: A→B, B→A의 "peer" 라벨에 `lo: [-22, 0]`, `[22, 0]`을 줘 서로 떨어뜨림.
- 잘림: 도식 높이를 줄여 프레임마다 카드가 밀리는 폭을 줄임(재촬영 전이라 확인 안 됨).
- 용어: `snapText`·`CAP.count[8]`의 "retainer"를 "보유 경로"로 바꿈.
- 권고 2건(unused-term '도달 불가', 'rc'·'Pair' 약어)은 그대로 둠.

audit 재실행: 고침 0건(권고 1건만 남음). 위 시각 수정은 audit이 잡지 않으므로 t1s·t4s·t8s 재촬영으로 확인이 필요하다.
