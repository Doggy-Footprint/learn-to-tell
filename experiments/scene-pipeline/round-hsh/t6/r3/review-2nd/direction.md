## 초안 분석
**a**: contrast 좌우. 쪽마다 diagram(루트·A·B)을 프레임 배열(생성→peer→peer→루트 해제→mark→sweep→gone)로 다시 그리고, 아래에 axisPlot·스냅샷 표. 생성 순서(A,B 생성 → A→B → B→A → 루트 해제)와 rc 계산(rc = 루트 + 들어오는 참조)이 스토리보드와 맞다. mark 쪽은 해제 직후 그대로 남고 GC 때 회수되는 지연이 보인다. 어긋남: 반복 중 힙 시계열이 쌍 100개를 7초에 몰아 그려 톱니 기준(16쌍 주기)이 읽기 어렵고, 전역 캐시 반전(비트 6)이 없다. 결함 코드는 없다(권고 shrunk만).
**b**: 직접 SVG로 A·B 박스와 화살표를 stroke-dashoffset으로 그려 순환이 "그려지는" 느낌이 좋다. 공유 시계로 두 쪽 동기. 어긋남: B가 A와 같은 시점에 생겨 "A 생성 → B 생성" 순서가 겹치고, 톱니 공식이 임계 12쌍 기준이라 사실 점검표(16 MB)와 다르다. 반전 없음.
**c**: diagram.player + send 패킷, 쪽마다 mock.terminal 스냅샷. 순서·rc 값은 맞다. 어긋남: rc "A=2·B=2"가 루트 해제 전 상태로 맞으나 A→B 단계에서 A=1·B=2 표기가 정확. 결함: 두 쪽 player가 독립이라 동기가 안 맞고, 톱니 공식 4+(n%16)*1 무난. 반전 없음.
**d**: 프레임별 상태(A, B 따로 생성) + player + trace. 생성 순서가 가장 정확(A 먼저, B 나중). 어긋남: diagram을 매 프레임 새로 그리고 player가 단계 `enter`에서 별도로 그려 이중 그리기, mark 쪽 sweep 후 반복 단계만 남는다. 반전 없음.

## 가져올 것
- a/d: 프레임 배열로 diagram을 다시 그리는 방식, rc = 루트 + 들어오는 참조 계산, mark 쪽 "GC 전 → mark 안 됨 → 회수" 지연.
- b: 공유 시계 하나로 두 쪽을 같은 박자에 맞춤, 화살표가 그려지는 느낌은 diagram 대신 프레임 단위로 대체.
- a: axisPlot 사용법.
- 새로 추가: 마지막 비트에 전역 캐시가 A를 쥐는 반전(mark 쪽).

## 최종 방향
뼈대는 contrast 좌(참조 카운팅)·우(mark-and-sweep). 쪽마다 위에 루트·A·B 그래프(주인공), 가운데 힙 타임라인, 아래 스냅샷 한 줄. 공유 시계 하나가 같은 박자로 비트를 민다. 비트: ① A 생성(rc1) ② B 생성 ③ A.peer=B로 B rc2 ④ B.peer=A로 A rc2 ⑤ 루트가 a,b를 놓음: 카운팅은 즉시 1,1로 멈추고 mark 쪽은 아무 일 없음 ⑥ GC: 카운팅은 해제 안 됨, mark는 루트에서 닿는 것만 표시해 A,B가 표시 없이 ⑦ sweep으로 회수. 이어서 100쌍 반복: 카운팅은 +1MB씩 100MB로, mark는 4~20MB 톱니(16쌍마다 GC). 마지막 반전: 스냅샷에서 카운팅은 retainer가 서로뿐, mark 쪽은 전역 캐시가 A를 쥐어 루트까지 이어져 회수되지 않음. 조작은 없고 자동 반복 재생(leave에서 정지). 글은 프레임 자막, 노드 부제(rc, 도달 상태), 스냅샷 한 줄만 얹는다. 순수 카운팅 모델이며 CPython은 순환 감지기를 더한다는 점을 basis에 적는다.
