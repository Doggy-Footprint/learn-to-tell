# direction

## 초안별
**a**: 은행 A→E 연쇄 diagram(예금·준비금·대출 라벨) 위에 누적 예금 선 플롯과 점선 상한, r 손잡이(20/10/5%). 라운드는 setTimeout으로 자동 전개, 대출은 `dg.send`로 다음 은행에 전달. 사실·순서는 맞다(예금 → 대출 → 다음 예금, r 변경 시 처음부터). 결함: 매 틱 diagram을 다시 만들어 깜빡이고, 그림이 작다(audit small-visual 6%), 준비금 합계 100은 문장으로만 있다.
**b**: 10개 은행 diagram + 라운드 표 + 누적 플롯 + 3개 큰 숫자. stepper 자동 재생. 숫자는 정확하고 준비금 누적이 표에 보인다. 결함: 표가 주인공이라 그림이 약하고(3%), 대출과 다음 예금이 같은 enter에서 동시에 켜진다. 상한이 라운드 4 이전부터 보이는 건 맞다.
**c**: 5개 은행 diagram + `dg.player`로 비트별 caption·send, 누적/상한 비율 막대. 캡션에 "예금 → 대출 → 새 예금" 순서가 명시되고 r 변경 시 재전개한다. 좋은 점은 순서 캡션. 결함: 그림 7%로 작고, 라운드 5개에서 끝나 수렴이 안 보인다. 대출 라벨을 d(i+1)로 미리 보여 준다.
**d**: 은행 수를 늘려 가는 diagram + stat 3개(준비금 총량 100 고정) + 진행 막대 + stepper. 준비금 불변 대비가 가장 분명하다. 결함: 그림 작음(4~6%), 단계 5개가 비트 설명 위주라 라운드별 생성 순서가 약하고, r 변경 때 단계 상태를 유지한다.

## 가져올 것
- c: 단계별 caption으로 생성 순서(예금 → 분할 → 대출 이동)를 말하는 방식, r 변경 시 처음부터 재전개.
- d: 준비금 합계를 큰 숫자로 따로 두어 예금 합계와 대비.
- a: 상한은 처음부터 고정된 점선, r 손잡이 steps 20/10/5, `leave`에서 실행 중단.
- b: 10라운드까지 전개해 수렴을 보이는 것.
- diagram은 쓰지 않는다. 작게 나오는 원인이라서 직접 SVG를 그린다.

## 최종 방향
그림의 뼈대는 폭포(waterfall) 막대다. 가로는 은행 A…J, 세로는 예금 누적액이고, 라운드 k의 새 예금 막대는 앞 라운드까지의 누적 높이 위에 얹힌다. 세로 축은 현재 r의 상한(D0/r)까지로 고정하고 상한은 맨 위 점선으로 처음부터 그려 둔다. 막대 하나가 은행 하나의 예금이다.
비트별 움직임, 라운드마다: ① 새 예금 막대가 생긴다(A는 최초 예금, 이후는 도착한 대출) ② 막대 아래쪽이 준비금(어두운색)으로, 위쪽이 대출(강조색)로 나뉘고 준비금 칸이 아래 줄에 적힌다 ③ 대출 조각이 오른쪽 은행으로 건너가 거기서 다음 예금 막대가 된다. 대출이 도착한 뒤에야 다음 라운드가 시작되고, 앞 두 라운드는 느리게, 뒤는 빠르게 돈다. 예금 합계는 막대가 서는 순간 커지고, 준비금 합계는 분할 때 쌓여 100을 넘지 못한다. 2라운드에서 "A 예금 100이 남은 채 B에 90이 생겨 합계 190" 캡션이 붙는다.
조작: 지급준비율 손잡이(20·10·5%). 바꾸면 전개가 처음부터 다시 돈다. 오른쪽에는 3개 상한(500·1000·2000)을 고정 축 가로 막대로 비교해 현재 r을 강조하고, 다시 재생 버튼을 둔다.
글: 그림 위 캡션 한 줄, 예금 합계·준비금 합계 큰 숫자, 해설은 지준율 인하가 상한만 올릴 뿐 실제 통화량은 대출 수요와 초과 준비금이 가른다는 주의로 끝난다.
