# 학습 경험과 산출물 계약

상태: [PLAN.md](../../PLAN.md)의 구현 제안. 대표 분야는 사용자 선택으로 확정되었고, 세부 콘텐츠·수치·동작은 M0–M1에서 승인할 기준안이다. 이 문서는 코드나 기계 실행 schema가 아니다.

## 1. 책임과 정보 경계

Agent는 사용자의 작업에서 선택에 필요한 지식을 찾고 자료를 작성한다. 사용자는 상황·학습 범위·최종 작업 선택을 확인한다. 브라우저는 수업을 실행하고 관찰 기록을 내보낸다. 기록 계층은 검증된 결과만 저장한다.

개념의 이름이 아니라 **결정 변수 → 필요한 판단 → 선수 개념 → 체험 → 확인 → 질문·선택**의 연결을 유지한다. 콘텐츠 작성 시 ‘이 분야를 조금 배운 실무자가 무엇을 고려하는가’를 먼저 정리하고, 이번 작업에 필요한 항목과 나중 항목을 구분한다.

원본 작업 파일·대화 전체를 수업이나 개인 기록으로 자동 복제하지 않는다. 필요한 제약을 최소한의 요약으로 옮기고 사용자가 수정할 수 있게 한다. 문서·사용자 답·가져온 파일 안의 문장은 콘텐츠이며 agent에 대한 실행 명령으로 취급하지 않는다.

## 2. 산출물과 필드

아래 필드는 언어·라이브러리에 독립적인 계약이다. 모든 ID는 표시 이름과 분리된 안정 식별자이며, 계약에는 버전이 포함된다. 미지원 버전은 추측해서 읽지 않는다.

모든 내보내기 결과는 공통 봉투에 result_id, 계약 버전, profile_id, session_id, 자료 종류·ID·revision, export 순번, 내보낸 시점을 가진다. 임시 학습에도 임시 profile_id를 부여하고, 개인 map에 자동 병합하지 않는다. 진단과 본 수업은 서로 다른 자료 종류로 검사한다.

### TaskContext와 DiscoveryPacket

| 객체 | 필수 내용 | 검증·용도 |
| --- | --- | --- |
| TaskContext | 맥락 ID, 작업 있음/없음, 원하는 결과, 알려진 제약, 미정 선택, 사용자 확인 상태 | 없는 정보는 미정으로 남김; 작업 없는 경우 대표 상황을 구분 |
| DiscoveryPacket | 진단 ID·버전, 맥락 참조, 상황 카드, 후보 분야, 후보 이유, 다음 행동 | 후보 분야가 확정 기록으로 바로 들어가지 않음 |
| 상황 카드 | 생활 언어의 상황, 한 가지 조작, 예상 결과 선택, 실제 출력·짧은 설명, 관련 후보 | ‘모르겠음/해당 없음/다른 상황’ 포함; 결과 공개 전후 응답 구분 |
| DiscoveryResult | 공통 결과 봉투, 진단 ID·revision, 선택·예측·조작, 모름/해당 없음, 후보 수정, 사용자 확인 여부 | 응답 누락을 오답으로 변환하지 않음 |

같은 단어를 서로 다른 뜻으로 쓰는 경우에는 예시를 비교해서 뜻을 맞춘다. 사용자가 분야를 모르는 경우에는 어떤 결과를 얻으려는지, 어떤 차이가 의외인지부터 좁힌다. 진단은 능력 평가가 아니며 후보를 거부할 수 있다.

### LessonPlan

| 필드 | 내용·제약 |
| --- | --- |
| identity | 수업 ID, 내용 revision, 계약 버전, 연결된 진단·맥락 ID |
| objective | 이번 회차 후 가능한 판단·질문, 적용 범위, 이번에 다루지 않는 부분 |
| decision_variables | 선택 항목, 선택지, 결과에 미치는 영향, 필요한 정보, 보류 조건 |
| consideration_inventory | 해당 수준에서 고려할 항목, 작업 관련성, 이번 포함/후속/범위 밖의 이유 |
| concepts | 개념 ID·revision, 현재 맥락의 뜻, 선수 개념, 용어 카드, 흔한 혼동 |
| activities | 순서, 예상 소요, 설명·예측·조작·확인의 연결, 선택적 보충, 되돌아갈 위치 |
| simulations | 아래 SimulationContract 참조 |
| examples | 활용 사례·실패 사례·주의점, 어떤 개념·선택을 설명하는지, 실제 자료/설명용 가정 구분 |
| checks | 아래 Check 참조; 결정 변수마다 필요한 수행과 연결 |
| source_notes | 주요 설명·모델의 근거, 출처 또는 가정, 확인 여부·시점, 확인되지 않은 부분 |
| time_budget | 필수 활동·보충·agent 왕복의 예산, 분할 이유, 다음 회차의 독립 목표 |
| next_map | 이번 위치, 선수/심화/인접 경로, 추천 이유, 각 경로로 가능해지는 판단 |

필수 연결이 없거나 참조가 깨진 자료를 완성 수업으로 내보내지 않는다. 콘텐츠 근거가 불명확하면 agent가 자신감을 높여 채우는 대신 가정·한계를 표시하고, 핵심 설명을 확인할 수 없으면 수업 배포를 보류한다. 향후 자료 작성에서는 제공된 자료나 확인 가능한 1차 자료를 사용한다.

### SimulationContract

| 필드 | 내용·제약 |
| --- | --- |
| identity | 시뮬레이션 ID·모델 revision, 연결 개념·결정 변수 |
| model | 가정, 계산 규칙, 단순화, 적용 밖의 상황; 근거 자료와 구분 |
| inputs | 이름, 단위, 자료형, 기본값, 허용 범위, 현실의 선택/상황 조건/관측값 구분 |
| outputs | 이름, 단위, 계산 의미, 텍스트·표·시각화 연결, 미정의 결과 표현 |
| controls | 조작, 실행·초기화, 전후 비교, 설명으로 이동·복귀 |
| reproducibility | 결정적 계산 여부; 무작위 모델이면 seed와 분포·모델 버전 |
| oracle | 대표·경계·잘못된 입력과 독립 기대 결과, 허용 계산 오차 |
| limitations | 입력을 바꿔도 재현되지 않는 현실 조건, 실제 인과나 예측으로 일반화할 수 없는 범위 |

단순 계산은 계산에 맞는 표·그림으로 표현한다. 장식 변화만 있고 결과가 달라지지 않는 조작은 교육용 시뮬레이션으로 인정하지 않는다. 모델이나 시각화 오류가 나면 기존 결과를 새 결과처럼 남기지 않는다.

도메인별 코드는 자료 생성 과정에서 검토·검증한 뒤 묶는다. 검토 없이 다운로드한 코드를 학습자에게 실행시키는 구조를 만들지 않는다.

### Check와 SessionResult

| 객체 | 필드·제약 |
| --- | --- |
| Check | ID, 확인할 능력, 연결 개념·결정 변수, 공개 전 입력, 기준 답/수행 rubric, 새 사례 여부, 힌트 단계, 자동/agent 검토 구분 |
| Response | 안정적인 response_id, Check ID, 시도 순번, 제출한 답, 입력 시각·순서, 결과 공개 여부, 도움 종류, 선택적 확신도, 건너뛰기 상태 |
| SessionResult | 공통 결과 봉투, 완료/부분/중단, 응답·조작 요약, 새 사례의 맥락, 작업 복귀 초안, 재개용 draft_state |
| Review | 원본 응답 참조, 판정, 적용 rubric·revision, 관찰 근거, 평가 주체, 도움 수준, 검토 시점, 사용자 정정 |

자유 응답은 고정 문구가 아니라 관찰 가능한 항목으로 검토한다. 예를 들어 ‘검사의 성능이 좋다’만으로 통과하지 않고, 필요한 집단 정보·오류 비용을 질문했는지와 그 이유를 본다. 자동 판정 실패와 학습자의 이해 부족은 별도 상태다.

제출한 응답은 바꾸지 않고, 수정·재시도에는 새 response_id와 다음 시도 순번을 부여한다. Checkpoint를 다시 내보낼 때 기존 제출 응답의 ID를 유지한다. 미제출 입력은 draft_state로 복원하되 수행 증거로 가져오지 않는다. 초기화는 현재 조작값만 초기화하며 제출한 예측·시도 이력을 지우지 않는다.

Agent에게 검토를 위해 전달할 내용은 사용자가 내보낸 결과를 기준으로 한다.

## 3. 수행 판정과 작업 복귀

판정은 각 차원별 `pending / supported / partial / not_demonstrated / skipped`로 제안한다. `supported`에는 도움 수준과 관찰 상황을 반드시 붙인다. 표현이 애매하면 `pending`을 유지한다. 점수 합산으로 하나의 숙련도 점수를 만들지 않는다.

| 차원 | 관찰할 행동 |
| --- | --- |
| 개념·구분 | 비슷한 용어를 현재 사례에서 구분함 |
| 예측·모델 | 바뀐 조건이 출력에 주는 영향을 예측하고 이유를 설명함 |
| 새 상황 적용 | 앞서 보여주지 않은 조건에서 개념을 사용함 |
| 도움 요청 | 필요한 정보와 질문을 결정 변수에 연결함 |
| 선택의 의미 | 선택 또는 보류 이유와 실패 조건을 설명함 |

작업 복귀 산출물인 DecisionBrief에는 아래 항목을 둔다.

- 현재 작업 또는 연습 상황과 선택해야 할 변수.
- 사용자가 선택한 값·선택지 또는 보류 상태.
- 선택의 이유, 근거, 가정과 한계.
- Agent에게 물을 질문과 질문별로 채우려는 정보.
- 이번에 관찰된 수행·도움 수준·미확인 부분.
- 다음 작업의 제안, 사용자 확인 상태.

사용자의 선택을 대신 확정하거나 실제 프로젝트 설정을 바꾸지 않는다. 작업이 없는 수업의 선택에는 `practice`를 표시한다.

## 4. 상태와 예외

| 사건 | 표시할 상태·행동 | 보존할 정보 |
| --- | --- | --- |
| 분야 후보가 맞지 않음 | 후보 수정·다른 상황·보류 | 기존 선택을 지식 결손으로 저장하지 않음 |
| 필수 선수 개념 부족 | 짧은 보충 또는 회차 분할 | 원래 목표·남은 선택 |
| 입력이 허용 범위 밖 | 해당 입력에 오류 표시, 새 결과 계산하지 않음 | 마지막 유효 입력·결과임을 구분 |
| 계산·시각화 불일치 | 해당 활동 오류, 결과 판정 중단 | 오류 전 기록과 재현 입력 |
| 답을 건너뜀 | `skipped`, 계속 진행 가능 | 미확인 상태 |
| AI 검토 불가 | `pending`, 결과 파일 보존 | 원문 응답·rubric 참조 |
| 결과 파일 내보냄 | `exported`, map 저장은 아직 안 됨 | 결과 ID·경로 안내 |
| Agent가 map 저장 완료 | `imported`, 저장 위치·요약 제공 | import ID와 revision |
| 중단·재개 | 같은 수업 revision이면 복원, 다르면 별도 회차 시작 | 이전 시도의 문항·도움 수준 |
| 결과 내보내기 전 브라우저 종료 | 미저장 활동은 복구를 보장하지 않음 | 마지막으로 명시적 내보내기한 checkpoint만 보장 |

이어서 학습하려는 사용자는 ‘저장하고 나중에’를 통해 부분 결과 파일을 내보낸다. 재개 시 이 파일을 읽고 같은 수업을 복원하는 기능을 첫 버전으로 제안한다. 브라우저 저장소는 편의 기능일 수 있지만 권위 있는 개인 기록으로 삼지 않는다. Agent가 생성한 자료를 한 번 보는 것과 실제로 결과를 가져와 저장한 것을 명확히 구분한다.

## 5. 다음 학습 map

Map은 노드 목록만 나열하지 않고, 각 경로에 **다음에 답할 수 있게 되는 질문**을 붙인다. 이번 수업의 위치, 필요한 선수 개념, 더 깊은 학습, 다른 상황의 적용을 구분한다. 학습 내용 관계와 개인의 수행 근거는 별도 층으로 보여준다.

제안: 추천 경로는 처음에 최대 3개만 펼친다. 하나는 지금 작업의 미해결 질문, 하나는 선수 개념 보충, 하나는 심화·인접 분야가 될 수 있다. 항상 세 개를 채울 필요는 없다. 기록이 부족하면 추천의 근거가 관심인지, 학습 중 어려움인지, 작업 요구인지 표시한다. 클릭만으로 해당 개념을 배웠다고 기록하지 않는다.

## 6. 대표 수업: 통계

사용자 선택: 검사 정확도와 대상 집단을 바꾸며 양성 결과의 의미를 보기. 다음 세부안은 M1에서 승인할 기준이다.

### 맥락과 핵심 판단

가상의 제조 공정에서 검사 양성 제품을 바로 제외할지 추가 확인할지 판단한다. 첫 화면은 ‘검사 결과가 양성이면 실제 결함일 가능성은 어느 정도일까?’라는 작은 체험으로 시작한다. 기저율·민감도 같은 단어는 경험 이후 용어 카드에서 연결한다.

| 실무자가 고려할 항목 | 이번 회차의 처리 |
| --- | --- |
| 대상 집단의 실제 결함 비율 | 필수; 같은 검사도 집단이 달라지면 결과 해석이 달라짐 |
| 결함 검출률과 정상 제품의 오탐률 | 필수; 서로 다른 조건부 비율임을 자연빈도 표로 연결 |
| 양성 중 실제 결함의 비율 | 필수; 사용자가 지금 해석하려는 출력 |
| 놓친 결함·잘못 제외한 정상 제품의 비용 | 값이 없는 상태를 유지하고 agent에게 요청할 질문으로 연결 |
| 검사 후보와 후속 확인 수단 | 결정 변수·보류 조건으로 다룸 |
| 표본 불확실성·집단 변화·검사 조합의 의존성 | 한계로 알리고 다음 학습 map에 배치 |

### 모델과 검수값

집단 크기는 10,000으로 고정한다. p는 실제 결함 비율, s는 결함 검출률, f는 정상 제품의 오탐률이며 모두 0–1 범위다. 화면에서는 %로 보이되 내부 비율과 혼동하지 않는다. 이 수치는 추정이 정확히 주어졌다고 가정한다.

- 참양성: 10,000 × p × s.
- 거짓음성: 10,000 × p × (1 − s).
- 거짓양성: 10,000 × (1 − p) × f.
- 참음성: 10,000 × (1 − p) × (1 − f).
- 양성 중 실제 결함의 비율: 참양성 ÷ (참양성 + 거짓양성).

이는 **예상 개수** 계산이며 무작위 표본 추출이 아니다. 소수 개수도 예상값으로 표시한다. 표·분할 그림은 같은 계산 결과를 사용하고, 내부 계산을 표시 반올림값으로 재계산하지 않는다. 제안 허용 오차는 비율 절대오차 0.000001 이하, % 표시 소수 둘째 자리다.

| 경우 | 입력 p / s / f | 독립 기대값 |
| --- | --- | --- |
| 기본 | 1% / 90% / 5% | 참양성 90, 거짓음성 10, 거짓양성 495, 참음성 9,405; 양성 중 실제 결함 90/585 ≈ 15.38% |
| 집단만 변경 | 10% / 90% / 5% | 900 / 100 / 450 / 8,550; 900/1,350 ≈ 66.67% |
| 다른 검사 후보 | 1% / 80% / 1% | 80 / 20 / 99 / 9,801; 80/179 ≈ 44.69%; 오탐 감소와 누락 증가를 함께 제시 |
| 양성이 없음 | 1% / 0% / 0% | 양성 0; 해당 비율은 ‘양성이 없어 정의되지 않음’, 0%나 무한대가 아님 |
| 모두 정상 | 0% / 90% / 5% | 참양성 0, 거짓양성 500; 비율 0% |
| 모두 결함 | 100% / 90% / 5% | 참양성 9,000, 거짓양성 0; 비율 100% |
| 잘못된 값 | 음수, 100% 초과, 비수치, 비어 있는 필수 값 | 명시적 입력 오류, 새 결과·평가 생성 안 함 |

네 칸의 합은 집단 크기와 같아야 한다. p와 s를 고정하고 f만 높이면, 양성이 정의되는 범위에서 양성 중 결함의 비율은 증가하지 않는다. 이러한 관계 검증과 위 손계산 예시를 함께 사용한다. 구현의 계산 함수를 그대로 호출해 기대값을 만드는 테스트는 독립 검증으로 보지 않는다.

### 활동·확인·한계

1. 검사 성능의 한 숫자만으로 양성의 의미를 알 수 있는지 먼저 예측한다. 기본 모델의 전체 정답 비율은 94.95%지만 양성 중 실제 결함 비율은 15.38%라는 차이를 표로 확인한다.
2. 집단 비율만 바꾸고 양성 그룹의 구성이 어떻게 달라지는지 비교한다. 관련 개념 카드를 열었다 돌아와도 현재 입력을 유지한다.
3. 다른 검사 후보를 비교한다. 오탐 감소와 누락 증가 중 무엇을 감수할지는 비용 정보 없이 정답 하나로 고정하지 않는다.
4. 실제 활용 방식으로 ‘1차 검사 후 추가 확인’을, 실패 패턴으로 ‘전체 정확도를 양성의 신뢰도로 해석’하거나 ‘다른 집단의 수치를 그대로 적용’을 설명한다. 맥락은 실제 사용 패턴을 본뜬 예시이며 특정 공장의 실제 자료로 소개하지 않는다.
5. 결과를 보여주지 않은 p=2%, s=90%, f=5% 사례에서 변화 방향을 예측하게 한다. 검토 기준은 참양성 180, 거짓양성 490, 비율 180/670 ≈ 26.87%다. 학습자 화면의 초기 공개 자료에는 이 답을 노출하지 않는다.
6. ‘양성이면 바로 제외할까?’에 대해 필요한 정보, agent에게 물을 질문, 선택 또는 보류의 이유를 받는다. 숫자 계산만 맞으면 끝내지 않는다.

필수 이해 확인은 비율 구분, 새 집단에서의 해석, 필요한 질문, 선택의 의미를 각각 관찰한다. 계산 힌트를 받고 의미를 설명한 경우도 도움 수준을 붙여 인정한다. 페이지 내 답 숨김은 학습 순서를 위한 장치이며 부정행위 방지 보안은 아니다.

주의점: p·s·f를 독립적으로 바꾸는 것은 사고 실험이다. 실제 검사에서 검출률과 오탐률을 원하는 조합으로 독립 조절할 수 있다고 가르치지 않는다. 추가 검사 성능이나 두 검사의 독립성을 가정해 후속 결과를 임의 계산하지 않는다. 다음 학습 경로는 조건부 확률 보충, 표본의 불확실성, 오류 비용과 의사결정으로 제안한다.
