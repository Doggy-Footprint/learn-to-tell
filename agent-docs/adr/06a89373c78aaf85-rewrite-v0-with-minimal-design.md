# v0를 폐기하고 최소 설계로 다시 작성한다

- Status: Accepted (2026-10-13)

## Context

v0(2026-10-03 ~ 10-08)는 제품 코드 약 3,500줄, skill 문서 약 290줄, 테스트 약 9,900줄이었다. 실사용 피드백보다 형식 버전 관리, 원자적 저장, 백업, 복구, 오프라인·접근성 검수를 먼저 구현했고, 피드백이 올 때마다 형식, 검증 코드, 테스트를 함께 고쳐야 했다. 기능은 브라우저에서 대화로 계속 옮겨 갔다(진단, simple 수업·퀴즈). v0 저장소와 git 기록은 삭제된다.

## Decision

v0 코드를 폐기하고 `learn-to-tell-PROJECT.md` 4장의 최소 설계로 다시 작성한다. 아래 설계 규칙은 판단 기준이며, 강제 장치는 두지 않는다.

1. 검증·복구·형식 버전 관리 장치는 실사용에서 문제가 확인된 뒤에 추가한다.
2. kit 어휘는 실제로 만든 수업에서 반복된 패턴을 보고 정한다.
3. spec → 독립 테스트 → verifier → mutation 워크플로는 kit 로직처럼 동작을 테스트로 고정할 가치가 있는 곳에 쓴다.

## Alternatives

- v0 구조를 유지하며 피드백을 반영한다: 기각. 설계가 바뀔 때마다 버전이 붙은 계약, 검증기, 테스트를 연쇄로 고쳐야 했다.

## Consequences

- Positive: 피드백을 반영할 때 함께 고칠 형식·검증 코드·테스트가 적다.
- Negative: 데이터 손상이나 형식 불일치가 실사용 중에 처음 드러날 수 있고, 그때 장치를 추가해야 한다.
