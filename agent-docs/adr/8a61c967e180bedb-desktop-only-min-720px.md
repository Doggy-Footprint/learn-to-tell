# 수업 화면은 폭 720px 이상 데스크톱 전용으로 한다

- Status: Accepted (2026-10-15)

## Context

수업은 `server/server.mjs`가 `127.0.0.1`에서 서빙하고, 코딩 작업 중 `/fork`한 세션에서 열린다. 수업을 보는 기기는 그 작업을 하는 컴퓨터다. 그런데도 kit는 폭 720px 이하를 휴대폰으로 보고 별도 레이아웃(한 열 접기, 장면 축소 대신 스크롤)을 두었다. 화면 점검(`?audit`)과 눈 검토도 1440×900과 390×844 두 크기에서 했다.

## Decision

지원 범위는 폭 720px 이상 데스크톱 브라우저다. 720px 이하 휴대폰 분기(`ltt-deck.js`의 720·440px 미디어 쿼리와 `fit`의 스크롤 분기, `ltt-ui.js`의 before/after 세로 쌓기, `auditScene`의 `narrow`)를 없앴다. 720px에서도 장면은 한 화면에 맞도록 줄어든다(최저 78%). 화면 점검은 1440×900과 720×900에서 한다. 폭 1000px 이하에서는 `shrunk`·`small-visual`·`loose-figure`를 판정하지 않는다(`compact`).

## Alternatives

- 휴대폰(390×844) 지원 유지: 기각. 수업 서버가 loopback에만 열려 있어 휴대폰에서 열 경로가 없는데, 수업마다 두 번째 레이아웃 설계, 점검, 스크린샷 검토 비용이 든다.

## Consequences

- Positive: 장면은 어느 지원 폭에서나 스크롤 없이 한 화면에 들어간다는 규칙 하나만 따르면 된다. 점검·눈 검토 크기가 데스크톱 기준으로 통일된다.
- Negative: 720px 미만 창이나 휴대폰에서 수업을 열면 레이아웃이 깨질 수 있다. 휴대폰 복습 경로를 만들면 레이아웃 분기와 점검 크기를 다시 들여야 한다.
